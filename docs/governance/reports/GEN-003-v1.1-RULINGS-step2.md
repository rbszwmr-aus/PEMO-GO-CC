## The CI gap — ruled, because green-while-blind is the one outcome that may not stand

CI has no toolchain step, so the two new guards cannot run there. You verified that `REQUIRE_DEPCRUISE=1` makes the skip **fatal** rather than silent — and that verification is what makes the close safe. It converts the dangerous state (CI green while the guards never execute) into a red that a human reads. Without it, merging these guards would reproduce, at the CI layer, the precise blindness this PID exists to remove.

Rulings:
- **Write scope for v1.1 is extended, narrowly, to `.github/workflows/governance.yml`** — for this one change only: add the toolchain install and build so the workspace `dist/` exports the guards resolve through actually exist, and set `REQUIRE_DEPCRUISE=1` so a skip is fatal. Nothing else in that file changes; the read-only token, the two-step shape and the no-write contract from GEN-005 stand.
- **`REQUIRE_DEPCRUISE=1` is load-bearing and mandatory in the committed workflow.** It is the reason the close is safe: with it, a guard that cannot run turns the job red, never green. This is the `--require-git` lesson one layer up — an oracle that can answer "nothing to check" in the environment that matters must be made to fail loudly instead.
- **The first CI run is the experiment, per principle 10.** You cannot prove the GitHub runner locally; the guards passed *where the toolchain exists*, and CI is where it might not. State that as unverified-until-it-runs, exactly as governance.yml was first shipped. When the first run goes red, separate the infrastructural red (checkout / install / build / toolchain absent — fix the runner) from the substantive red (a guard fired on a real violation — read the code). Neither is ever a reason to drop `REQUIRE_DEPCRUISE=1` or loosen a rule to get green.

## Three flags you raised, each ruled so nothing travels unverified

1. **The other three depcruise rules' zeros are now new measurements, not confirmations.** `tsPreCompilationDeps: true` widened what they see, so any earlier green from them meant less than it appeared — the same class as F2. 2. **The battery now mutates real source, and SIGKILL is uncoverable.** The trap covers `EXIT INT TERM HUP`; a hard kill mid-boundary-case would leave an injected cross-module or simulator import in real source. Two things bound this, and I want both: first, note that such a leftover is **self-catching** — it is itself a violation the very guard that injected it would fire on, so it cannot pass the battery on a later run. Second, add a **pre-flight byte-identity check** at battery start: if a boundary-case target differs from `origin/main` before the run begins, abort, because that difference means a prior run was killed mid-mutation. Prove it by making it fail — kill mid-run, restart, show the pre-flight aborts. `prove.sh` is in scope, so this lands in the same commit.

3. **The `no-module-to-module` exemption `^(modules/platform/|modules/$1/)` is correct.** `modules/platform/` is the shared kernel every module may depend on, and same-module is not a cross-module edge. The 32 → 0 collapse was 32 intra-module false positives clearing, and that 0 is now a measurement, not an artefact. Accepted.
