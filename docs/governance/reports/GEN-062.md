## Root cause — `[git-tracking-is-not-existence]`

git does not track an empty directory. prove.sh already handled an *empty* `pids/` (GEN-046's synthetic
victim) but assumed the directory itself exists; on a fresh CI checkout where `pids/` is empty, git
materialises no `pids/`, so the snapshot, the synthetic victim and `restore()` all cp against a missing
directory. It passed my pre-push hook because my local worktree still held the empty directory on disk —
the on-disk remnant hid the absence a clean checkout exposes. Confirmed: the built worktree at 3d4a256
passes the battery (31/0) with the directory present; a fresh checkout has no `pids/` at all (the
GEN-062 worktree itself came down without one).

## Fix, guard, bite

- `docs/governance/pids/.gitkeep` (tracked) — `pids/` survives an empty state in git. Not a `*.md`, so
  pid-index and the synthetic-victim path are unaffected.
- prove.sh `mkdir -p "$GOV/pids" "$GOV/archive" "$GOV/reports"` before the snapshot — the battery no
  longer assumes the directory exists. Reproduced the CI condition locally (`rm -rf pids/`): green.
- `docs/governance/bin/pids-dir-tracked.mjs`, wired into the prove.sh battery — reds if git tracks
  nothing under `pids/`. **Bite:** `git rm --cached .gitkeep` → reds naming the cause; re-add → green.

## Verification

- prove.sh with `pids/` absent: green (was red). With the keeper untracked: `pids-dir-tracked` reds.
- The natural experiment: run 33936770015 red for this exact reason; the fix greens the register job.
- Principle `[git-tracking-is-not-existence]` cited, worked note added for the directory-absence scale.
