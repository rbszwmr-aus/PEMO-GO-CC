## Origin — a contradiction, resolved to the machine

Resolving the GEN-056 version question: the PO relayed `flutter --version` = 3.44.3; this host reports
3.44.9, and both cannot be true of one machine. Read the machine:
- `which -a flutter` → nothing. Flutter is **not on PATH** here; it answers only by explicit path.
- Exactly **one** SDK existed: `~/tools/flutter-3.44.9`. No `~/flutter`, no second dir, no symlink.

So the PO's 3.44.3 was a different machine (the PO's own), and my GEN-056 local runs were on 3.44.9 —
one patch above the gate's pinned 3.44.3. Not a two-SDK PATH ambiguity; the opposite — nothing on PATH.

## What landed (decision: OPTION 2 — pin the local toolchain)

- **3.44.3 installed ALONGSIDE 3.44.9**, not replacing it. The Flutter SDK is itself a git repo, so this
  was a local `git clone` of the existing SDK at the `3.44.3` tag + bootstrap (needed `unzip`, which was
  installed): `Flutter 3.44.3 • engine e1fd963c6f • Dart 3.12.2` — the pin's toolchain exactly.
- **`apps/resident-mobile/tool/flutter-pinned.sh`** — the local runner. It DERIVES the pin from
  `.github/workflows/governance.yml`'s `flutter-version` (never typed in the script, so it cannot drift
  from the gate), resolves the SDK EXPLICITLY (never via PATH — PATH is what made "what ran"
  unidentifiable), and asks the binary its version, refusing if it is not the pin. **The workflow is
  untouched; the CI pin remains the source of truth and the runner follows it.**

Shape chosen: the runner reads governance.yml directly (your primary option), not a new shared file —
it needs no workflow change, and a runner that parses the gate's own pin cannot drift from it.

## Bite (`run-mutations GEN-061`, kind guard, 1 proven)

Point the runner at a hermetic fake SDK reporting `Flutter 9.9.9` → it refuses, naming the resolved
version and the pin. The fake SDK is built inside the bite, so it needs no second real install and
bites identically in CI's hermetic run-mutations. `expect` is pin-independent ("a local run on ... is a
guess, not a gate"), so a legitimate pin bump does not silently pass it. Also proven by hand against the
real 3.44.9 install: refuses naming 3.44.3, exit 1.

## Verification

- Runner resolves 3.44.3 and reports it; the bite refuses 9.9.9 and the real 3.44.9.
- **The GEN-056 resident-mobile suite, run THROUGH this runner on 3.44.3: 280 tests, all pass** — so
  GEN-056's local claim is upgraded from "green on 3.44.9" to "green on the gate's pinned 3.44.3".
- `run-mutations GEN-061`: 1 proven, 0 failed. `adrs-present`: the new principle resolves.
