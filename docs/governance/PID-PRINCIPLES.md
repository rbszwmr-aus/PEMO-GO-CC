# PID principles — the engineering method

The most valuable non-code asset of the first build. Each principle is paired with the defect class it was learned from. Append-only; add a principle only with the incident that earned it.

**Entries are recorded from whichever session earned them; the report trail holds the evidence. An entry is not a finding of the session that wrote this file.**

## How to cite a principle

Every entry carries a **stable id** in backticked brackets — `` `[frozen-axis]` `` — and a report cites that id, never a paragraph, a position or a number.

**The rules the id obeys, and each exists because of a defect this corpus actually had:**

- **An id is permanent.** It never changes and is never reused, even when the entry's wording is amended. `[destructive-target-confirmed]` gained an ordering clause in `GEN-012` and kept its id, so every earlier citation still resolves.
- **An id names the principle, not its position.** Positions moved every time a principle was added, which is why the five historical numeric citations below stopped resolving at all.
- **An entry acquires its id when it is written**, not when it is first cited. A scheme with standing exceptions reads as a suggestion — `docs/adr/README.md` learned that about its own header fields — so all 55 entries carry one, including the ones nothing has cited yet.

## On proving

- `[prove-by-making-it-fail]` **Prove by making it fail.** An assertion is trusted only when its red condition has been shown to fire — mutation testing, deliberate defect injection, or reading the artifact the assertion produced. Every real defect in the first build was caught this way; inspection caught none. A green whose red is unknown proves nothing.
- `[inherited-green-not-earned]` **The inherited green is not all earned.** A passing suite is not proof until you know what each test would fail on. The first build's suite passed while carrying at least four independent holes, each found by `DOC-002` by making it fail: **presence, not execution** (a test asserting a file exists, never that it applies); **silent skip** (a test that skips on unset env and reads as green); **git-dependency masking** (a test green only because `.git` is present, un-runnable from an export); **contract-green over a live leak** (the suite green while the server emits a resident-only type on the management surface). When you inherit green, re-earn it — carry the code, not the confidence.
- `[fix-opens-new-failure-mode]` **A fix can open a new failure mode, and the check written for the old world cannot see it.** Strengthening a rule changes the space of reachable corruptions. When you amend a rule, re-ask what the *existing* guard can no longer see — the new hazard is usually adjacent to the thing you just made load-bearing, and the guard will keep passing while blind to it. Incident: rule 7's file-moves amendment made the archive leg load-bearing and simultaneously made a second duplicate shape reachable — one id in both `pids/` and `archive/` — which the reference one-liner cannot see, because `sort -u` collapses the pair before the number is extracted. The principle's first confirmation was the PID that files it: removing `reports:` made the very next file the guard saw break against it, the hazard sitting immediately adjacent to the field being made obsolete.
- `[expected-red-stops-being-read]` **A check that is expected to be red is a check that stops being read.** A guard may be red only while someone is actively fixing it; a knowingly-red guard left standing teaches people to skip the output, and it takes the guards beside it down with it.
- `[authority-defect-window]` **An authority defect that was live for a period makes every closure, merge and generation in that period suspect until checked.** Repairing the instances you found and stopping there leaves the class open while reporting it closed. Enumerate the window and check its work against the amended rule, not the rule in force at the time — and report "nothing else" explicitly when that is the answer.
- `[first-red-is-diagnosed]` **A new check that goes red on its first real run is diagnosed, never loosened.** Separate an **infrastructural** failure (the check could not run — a runner, a toolchain, a missing dependency) from a **substantive** one (the check ran and the thing it guards is wrong) before touching anything. They demand opposite responses and they look identical in a CI summary. A check weakened to obtain a green is weaker forever, and the weakening always looks reasonable in the moment because the red was "not a real failure".
- `[principle-is-not-a-control]` **A principle is not a control.** Recording a class does not defend against it — only a check that fires does. When a class recurs after being written down, build the check; do not write it down more emphatically. Evidence: a recorded restore-to-HEAD failure was repeated by its own recorder within the hour, and the **battery** caught it while the principle did not.
- `[negative-test-disarmed]` **A negative test can be disarmed by its environment and still report success.** Before trusting a proof that something fails, confirm the failure path was actually reachable when the proof ran. A trapped signal delivered during a long-running command is deferred until that command completes, so the interrupt never lands where the test assumed. Distinct from *a green whose red is unknown*: here the red was attempted, and silently neutralised.
- `[specific-assertion-catches-decay]` **A test that asserts a specific expected outcome catches its own decay; one that asserts only "no fault" rots silently.** The battery asserts an exact exit code per case, so six mutations that changed nothing produced six red lines instead of six greens — had the assertion been "no fault raised", all six would have passed while testing nothing. Specificity is what makes a test able to notice that it stopped working.
- `[regression-tests-the-older-callers]` **When a CLASS defect is fixed, the regression test goes against the callers that PREDATE the fix — the ones written alongside the rule are correct by construction and are the weaker half of the evidence.** A new call site written by the person holding the rule in mind will satisfy it; it proves the author understood the rule, not that the rule is enforced. The sites that were already there, written before anyone knew the rule existed, are where the defect lives and where a regression will reappear. `GEN-027` found that a refused act was still audited, fixed it, and wrote the standing test against `recordOccupancy` — an older caller, and the one the defect was found on — rather than against the grant operations built in the same PID. `GEN-028` then generalised it to every command that can refuse, and mutating one OLDER call site's declaration to the wrong-but-plausible `() => true` reds exactly that case. **Distinguished from `[specific-assertion-catches-decay]` by** what is chosen: there the assertion's CONTENT is made specific enough to notice decay; here the SUBJECT is chosen — which caller the assertion is pointed at — and a perfectly specific assertion aimed only at new callers still misses. **And distinguished from `[prove-by-making-it-fail]` by** what is established: that one asks whether the test can fail at all; this one asks whether it is watching the code that will actually break.
- `[guard-false-positive-rate]` **A guard's false-positive rate is a safety property.** A check that cries wolf gets switched off, and a switched-off check protects nothing. Earned twice: the `npx` guard flagged its own ban before it matched command position only, and the migration pre-flight aborted on a file nobody had touched because it hashed the output of a failed `git show`.
- `[all-preconditions-before-mutation]` **A guard that validates, mutates, then hits a second failure mid-mutation is worse than none — it half-applies before anyone knows.** All preconditions are checked before any mutation. `0115`'s down migration checked multi-member groups, passed, altered the schema, then died re-adding the old constraint on a second irreversibility it had never looked for.
- `[empty-oracle-family]` **The empty-oracle family.** A derived expectation that comes back empty agrees with a resolver that returns nothing — both are "no rows". Add a non-vacuity check: assert the expectation is non-empty before comparing. A test that cannot fail is not a test. **Distinguished from `[anchor-the-discriminator]` by** where the emptiness comes from: here from the **data** a derivation produced, cured by asserting it is non-empty; there from the **instrument**, a filter that discarded the match before anyone saw it.
- `[check-scoped-to-location]` **A check that reads a location goes quiet when the data leaves that location.** Enforcement scoped to where evidence *currently* sits is only as wide as a filing convention — and it fails silently, presenting as a clean result, exactly when the convention changes. The `GEN-001` allocation guard scans `pids/` + `reports/`; a closed PID's file stays in `pids/` only by convention (rule 7 moves the *row*). Move those files to `archive/` and the numbers vanish from the scan: `max(NNN)+1` walks backwards and the duplicate check goes quiet **because the evidence left the directory it reads**. The fix is to scope the check to the *rule* ("a number, once allocated, is never reissued") rather than to today's layout — scan the archive too. Ask of every check: what would have to move for this to stop seeing what it guards? **Distinguished from `[anchor-the-discriminator]` by** why the check went quiet: here the evidence **moved out of** the place it reads; there the evidence never moved and the search's own filter threw it away.
- `[anchor-the-discriminator]` **A line-based exclusion filter discards the WHOLE LINE, so it can hide a genuine match that shares a line with an excluded one — and a search that answers "none" ENDS THE LOOKING.** The second half is what makes the first dangerous: a filtered search reporting nothing does not merely miss a hit, it retires the question. `GEN-026` renamed an audit `source` value and checked for leftovers with `grep "'staff'" | grep -v estate_staff`, which reported none. `harness-isolation.test.ts:33` carried **both** tokens on one line — the source `'staff'` and the role `'estate_staff'` — so the exclusion discarded the line along with the live site inside it. The suite caught it; the search had already said the work was finished. **Re-run unfiltered and read the matches.** Exclude at the point of *judgement*, never at the point of *retrieval*: narrow by anchoring what you are looking for, not by throwing away lines that also contain something else. **Distinguished from `[empty-oracle-family]` by** what is empty: there a derived **expectation** comes back empty and silently agrees with an empty result, so the cure is a non-vacuity assertion on the expectation; here the **search itself** returns empty because the instrument threw the answer away, and the cure is to re-run without the instrument. One is a test that cannot fail; the other is a look that cannot see. **And distinguished from `[check-scoped-to-location]` by** what excludes: there the evidence has **left the place** the check reads and the fix is to widen the scope to the rule; here the evidence is **in front of the check** and the filter discards it, and the fix is to stop filtering. Same symptom — a confident "nothing found" — from opposite causes: one looked in too few places, the other looked in the right place and deleted what it saw.
- `[self-reported-blast-radius]` **A self-reported blast radius is a claim to verify, not a fact.** A file that says "removing this touches one migration" is asserting its own reach; measure it. `DOC-002` found the "delete, do not migrate" scaffold header claimed one file and `DROP SCHEMA` made 33 tests fail. The self-report is exactly the number a migration PID would have planned against — so it is the number to prove false before planning.
- `[name-the-code-path]` **Name the code path before requiring a state.** A requirement that a state be exercised is a claim that the state is reachable. Before requiring it, name the code that produces it; if naming it means reading the implementation, read it.
- `[fixtures-are-owner-work]` **Fixture setup and teardown are owner work.** A test that performs them through the application credential cannot distinguish *"the app is forbidden this"* from *"my fixture could not run"*. Route fixtures through the owner handle and let the app credential exercise only application behaviour. The distinction was invisible while one credential did both — which is how a test came to delete a grant it existed to prove the app cannot.
- `[probe-passes-on-permission]` **Corollary: a negative probe on the application credential passes on permission, not on the thing it means to prove.** `assert.rejects(db.query(INSERT …), /some_constraint/)` issued as the app fails on the **permission wall** before the constraint is ever evaluated, so the assertion passes for the wrong reason and the constraint is untested. One `adr-006` file held 17 such writes, failing to run rather than failing loudly, and nothing would have shown them until an ordering change lit them.
- `[hazard-window-mutation]` **A green suite is worthless if reintroducing the defect it exists to catch keeps it green — and the reintroduced failure must land in the actual HAZARD WINDOW, not merely somewhere in the flow.** Prove the suite by mutation: put the defect back and confirm a test fails. `GEN-011` put GEN-009's cross-transaction audit back and all six tests stayed green, because every injection was *before* or *as* the audit and none was between the audit and the commit — the entire window in which the two designs differ. A mutation test in the wrong window is an empty oracle with extra steps.
- `[git-tracking-is-not-existence]` **Git tracking is not existence.** A tool that reads the filesystem acts on what is on disk, tracked or not — so enumerate the filesystem and then interrogate git per file, never ask git what exists, or the scan inherits git's blind spot as its own. It cuts both ways and has bitten in both directions: an *ignored* PID file is visible to `readdir` and invisible to `git status`, so its number would be held in the register and absent from the repository (`GEN-001`); and an *untracked* migration is invisible in a diff and fully visible to the migration runner, which reads the directory — `GEN-011` spent a table-count discrepancy of one discovering that `0116` had been applied on every bootstrap for two PIDs. **WORKED NOTE — THE ABSENCE OF A DIRECTORY, ONE SCALE UP (`GEN-062`).** git tracks no *empty* directory, so closing the last open PID emptied `pids/` and a fresh CI checkout materialised no `pids/` at all — and the governance battery, which `cp`s a snapshot of it, reddened for a reason unrelated to any guard. It passed the pre-push hook because the author's worktree still held the empty directory on disk: **the on-disk remnant hid the absence that only a clean checkout exposes** — the same trap as the ignored file, now about the directory itself rather than a file in it. Fixed with a tracked `.gitkeep` (the directory survives an empty state in git) and a `mkdir -p` in the battery (it never assumes the directory it works in exists), guarded by `pids-dir-tracked.mjs`.
- `[the-seed-is-the-world-the-fixture-is-a-photograph-the-test-builds-its-own-props]` **The seed says what exists; a fixture records what was seen; a test constructs whatever it needs to make a named target go red — and must, when the world is too quiet to tell a correct implementation from a broken one.** A counter of 0 satisfies `count == list` for every implementation, correct or not: over `0 == []` the assertion has no teeth. `GEN-064`'s seed holds no safety event, no retracted event, and no non-residential unit in an unknown state, so DISTINCT-`event_id`, `retracted = false`, and residential-only would all ship green under deletion — three rulings shipped untested. The remedy is neither padding the seed (which makes the fixture lie) nor loosening the assertion: it is test data created in the test and torn down with it — a safety event whose audience spans several units so join-row counting differs from distinct-event counting; a retracted event inside the window; a non-residential unit carrying an unknown severity; occupancies under two buildings so a tree count is proven PER NODE, not per estate. Each with its instrument control: remove the condition, watch the named assertion red, restore. **Distinguished from `[the-empty-case-arrives-last-and-is-tested-never]` by** which quiet the test must break: there the collection's own empty state, reached in production and never exercised; here the world's incidental quiet, which hides whether a predicate has teeth at all.
- `[the-empty-case-arrives-last-and-is-tested-never]` **The empty case arrives last, and is tested never.** A collection that has been non-empty since it was created reaches empty for the FIRST time only after a long habit of being full — so its empty state is the least-exercised path in the system, and every line that touches it was written by someone who had only ever seen it populated. The emptiness is not an edge the author declined to handle; it is one they never saw. TWO instances in two days: `flutter-test-debt.json` emptying broke the flutter gate's own tests, which passed BECAUSE a debt existed (`GEN-056` B, `[correlated-lists-certify-nothing]` from the other side — the coupling only shows when the list empties); and `pids/` emptying dropped the directory from a clean checkout and reddened CI (`GEN-062`, `[git-tracking-is-not-existence]`). **When a collection, directory or file CAN reach empty, exercise the empty state before it arrives on its own: a TEST where emptiness is legal, a CHECK that reds where it is not.** The deliverable is the enumeration — every collection whose emptiness is reachable, with two verdicts each (can it legitimately be empty; is that state exercised today) — because the survivors are found by listing them, not by remembering them. Its two instances above each reduce to a named principle at a different layer — `[correlated-lists-certify-nothing]` for the debt file, `[git-tracking-is-not-existence]` for the directory — and what unites them is not the mechanism but the trigger: the first arrival of a value the population has never held.
- `[redundant-check-is-a-witness]` **A redundant check is a witness.** Removing a check that "never fires" promotes whatever it was witnessing to unguarded. Before deleting one, find what breaks when it is gone; if nothing does, it was load-bearing in a way you have not seen yet.
- `[premise-maintained-elsewhere]` **A change's correctness can rest on an invariant maintained somewhere else; removing that invariant later makes the change wrong WITH NO EDIT TO IT.** The reasoning is recorded in the dependent code — often as the comment justifying why something is safe to simplify — while the thing that makes it true lives in another file, another module, or a migration. Nothing links them, so the constraint's removal reads as local and the dependant's comment goes on asserting a premise that has evaporated. **When dropping a constraint, look for what ELSEWHERE was justified by its existence** — grep the reasoning, not just the references. `GEN-024` removed `findGrantsAsAt`'s `SELECT DISTINCT` on the true-at-the-time reasoning that *grant_id is the row identity, so every row was already distinct* — true only because `group_membership_no_overlapping_periods`, in another module's migration, made a duplicate membership unwritable. `GEN-029` dropped that constraint to make removing a member expressible, which would have made the earlier removal retroactively wrong in a file it never touched; the deduplication was restored **in the same diff**, its comment rewritten to say why it is there NOW, and given a test that reds if it is deleted again. **Distinguished from `[redundant-check-is-a-witness]` by** which side is examined: there the CHECK is the subject and the question is what it silently guards; here the check is being deliberately removed for a good reason, and the subject is the DEPENDANT — code elsewhere that cited the check as a premise and will not change when it goes. **And distinguished from `[stale-read-travels]` by** what decays: there a VALUE read at one moment is carried somewhere it is no longer true; here a JUSTIFICATION is, and it decays silently because no value moved at all.

- `[patch-verify-on-disk]` **A patch script's own success report is not evidence that the file changed.** A multi-edit script that batches its writes discards every earlier edit when a later anchor fails — and it has already printed `ok` for them. Verify each edit **on disk** by re-reading, or write once per edit. Bit three times: `GEN-014` shipped a stale `info.summary` because `GEN-013`'s edit was announced and never written and nothing noticed for a whole PID; `GEN-015` and `GEN-016` each lost an edit the same way and caught it only by re-reading. **The corpus already carried the discarded-exit-status lesson; this is the same class one layer up, in the tool rather than the shell.** **Distinguished from `[merge-gate-precondition]` by** the fix: here a tool's **self-report of its own effect** was trusted, and the remedy is to observe the real artifact on disk; there an action was gated on the **wrong exit status**, and the remedy is to wire the gate to the status that matters. Same root — an unverified status — different sites and different fixes. **And distinguished from `[probe-must-bite]` by** the moment: this one is about an **edit** you believe you made; that one is about a **probe** you believe changed the input a check reads.
- `[probe-must-bite]` **A probe used to prove a check must itself be verified to have changed what the check reads.** A mutation that silently fails to apply produces a green run indistinguishable from a check that does not fire — and it reports the *check* as broken, or worse, as fine. Confirm the probe altered the observed input before trusting either colour. `GEN-019` hit it twice in one sitting: a `sed` pattern that never matched a file reported the amendment arm green and nearly recorded a check failure that was a probe failure, and a vacuity attempt that did not narrow the scan left an untested guard recorded as tested. **WORKED NOTE — THE MUTATION MUST EXPRESS THE REALISTIC WRONG IMPLEMENTATION, not a syntactic weakening.** A probe that bites is not enough if what it injects is not a defect anyone would have written: a green under an unrepresentative mutation proves nothing in either direction, because neither the check nor the code has been asked the real question. `GEN-027` weakened the provisioning predicate from *zero grants ever* to *zero live grants* by bolting a liveness clause onto the raw scan — and all 298 tests stayed green, because the weakened SQL still matched the instance's open version-1 row. **The mutation was wrong, not the test.** The implementation someone would actually have written resolves the latest assertion and then tests liveness, and against THAT the test reds. Ask of a surviving green: is this the defect I meant to inject? **Distinguished from `[patch-verify-on-disk]` by** what is being verified: there, that an **edit landed on disk** — trust the artifact, not the tool's success report; here, that a **probe actually changed the checked input** before its red or green is believed. Same root — an effect assumed rather than observed — at two different moments. **WORKED NOTE — a CONCURRENCY probe must be shown to actually OVERLAP.** *Issued together* is not *racing*: two calls made with `Promise.all` each take milliseconds, so the first transaction commits before the second one reads, and the second then refuses correctly **with or without the mechanism** — the test measures sequential execution, which is true of anything. The technique is to **hold the transaction open inside the callback** (a `setTimeout` after the act, before the return) and to mark that line load-bearing where it sits, because it reads like tidyable noise. `GEN-016` first used it for the occupancy advisory lock; `GEN-024` did not carry it forward and its concurrency test **passed with the lock deleted**, which is what surfaced the gap. `GEN-025` then found the second half of the same trap: both racers wrote the **same row id**, so the act was serialising itself on its own primary key and the probe still passed with the idempotency mechanism removed — **the racing writes must not collide on anything except the mechanism under test.** Recording the technique, not just the lesson, is what stops the next re-derivation. **And distinguished from `[context-inherited-env]` by** the subject: this one is about the **probe** you feed a check; that one is about the **environment the check itself inherits** from whatever invoked it.
- `[mutate-to-the-plausible-wrong-rule]` **A guard is proven to bite only by mutating it to a COMPETING RULE A REASONABLE AUTHOR MIGHT HAVE WRITTEN — not by deleting it.** A syntactic deletion is the weaker probe in three ways, each of which this corpus has now met. It may **not compile**: `GEN-033` could not delete the registration floor at all, because the witness requirement and the org-node coverage are one statement, so the probe had to be re-aimed at the coverage alone. It may red **for an unrelated reason**, proving only that something downstream needed the code, not that the check was watching the thing it claims to. And it may **not be a defect anyone would ship**: `GEN-027` weakened a zero-grants-EVER predicate by bolting a liveness clause onto the raw scan and all 298 tests stayed green, because the weakened SQL still matched an open version-1 row — the mutation was wrong, not the test, and the implementation someone would actually have written (resolve latest, then test liveness) reds. **Ask: what would a careful person have written instead?** Then write that. `GEN-033` proved five guards this way — conjunction to any-node, empty-set to vacuous-pass, floor-to-any-administrator — each a rule with a plausible case for it. **Distinguished from `[probe-must-bite]` by** which half is in doubt: there whether the probe CHANGED the input at all; here whether what it changed it to is the defect the guard exists to stop. A probe can bite perfectly and still prove nothing.
- `[context-inherited-env]` **A check that runs in more than one invocation context must be proven in the context that gates.** A git hook, CI and a standalone shell are not the same environment: git exports `GIT_DIR`, `GIT_PREFIX`, `GIT_EXEC_PATH` and more into every hook, CI sets `CI` and `GITHUB_ACTIONS`, and children inherit all of it. An inherited variable can make a check **find what it must not** or **miss what it must catch**, and the check's source is identical in both. `GEN-022` measured it: run inside the new pre-push hook the battery reported `21 passed, 2 failed` where standalone it was `23 passed, 0 failed` — the two cases that prove the generator notices it has *no* repository found one anyway, through an inherited `GIT_DIR`. The hook strips git's injected variables for its children (`env -u`, not `unset`, so the hook's own `git` still works), because the hook is the abnormal context and the battery should not have to defend itself against every caller. **That mis-report was fail-safe — toward failure, which is recoverable; a check made to pass spuriously by an inherited variable ships a gate gating less than it claims, and says nothing.** **Distinguished from `[assert-the-isolation-level]` by** what varies: there a **running context's configuration** (the isolation level) is assumed rather than asserted, and the cure is to read it and refuse; here the **invocation context's inherited environment** differs between callers, and the cure is to run the check in the context that gates and control what it inherits. **And distinguished from `[probe-must-bite]` by** what is unproven: there a **probe** is assumed to have changed the input a check reads; here the **check itself** is assumed to behave the same wherever it is invoked. Same root — an unverified assumption about the conditions a check runs under — at three different layers.
- `[a-local-run-on-a-different-toolchain-is-a-guess-not-a-gate]` **A local run on a different toolchain than the one that gates is a guess, not a gate.** "Green locally" only means anything if it ran the tool CI runs; a version one patch off can pass what the gate would catch — which is the whole class this repo has paid a day a week for (the reporter format, the missing `origin/main`, the boundary scanner), each a local check that ran something CI did not. `GEN-061` found Flutter reachable on this host ONLY by an explicit path (`which -a flutter` empty) and one patch above the pin (3.44.9 vs the workflow's 3.44.3), so a bare `flutter test` neither identified what ran nor matched the gate. The runner resolves the SDK the workflow pins — reading `flutter-version` from `governance.yml` so it CANNOT drift from the gate, never typing the version a second time — and, because a directory name is not proof of a version, asks the binary and refuses if its reported version is not the pin. **The pin stays the source of truth and the local runner follows it; deriving the check's expectation from the gate's own declaration is the shape that cannot rot.** **Distinguished from `[context-inherited-env]` by** what differs between the two runs: there the same tool inherits a different ENVIRONMENT from its caller; here a DIFFERENT BUILD of the tool answers, and the cure is to pin and verify which build ran. **And distinguished from `[correlated-lists-certify-nothing]` by** direction: there an expectation and its subject drawn from one source certify nothing; here an expectation (the pin) deliberately drawn from the gate's own source is exactly what keeps the local check honest.
- `[identity-by-self-declaration]` **A thing is identified by what it declares itself to be, never by the shape of its name.** A filename, a prefix or a path is a convention that a neighbouring artifact can satisfy by accident. `GEN-017`'s ADR presence check resolved an id by globbing `ADR-NNN-*.md`, so `ADR-012-ACCEPTANCE-…` answered for a deleted `ADR-012` — a hole introduced *by the same commit that carried the acceptance records in*, and visible only because the proposed red was actually run and stayed green. Keying on the document's own `# ADR-012 —` heading separates the decision from its acceptance record and its amendment mechanically. **Ask what an impostor would also match.** **WORKED NOTE — THE SAME CLAIM AT A SECOND SCALE: A REQUEST IS IDENTIFIED BY WHAT THE CLIENT SENT, NEVER BY WHAT THE SERVER FILLED IN.** `GEN-027`'s idempotency fingerprint digested the RESOLVED `effectiveFrom` — a field that defaults to the request instant when the client omits it — so every attempt hashed a fresh timestamp and an honest retry was refused as a different request. The identity had been taken from the surroundings rather than from the subject's own declaration, and the caller was punished for the server's contribution to it. Fingerprint the CLIENT'S values; a server-supplied default is context, not identity. **The general form: an identity is whatever the subject itself declared — not its filename, not its neighbours, and not the values something else supplied around it.**
- `[shadowed-layer-empty-oracle]` **A gate standing behind an earlier gate cannot be seen to fire, so it needs its own layer-local oracle.** When one layer answers first, a mutation to the layer behind it leaves the suite green — the check is real, unreachable, and indistinguishable from its own deletion. `GEN-013` deleted the in-query filter and all thirteen tests passed, because the route's grant lookup answered 404 first. Test the decision **where it is made**. A suite that stays green under the shadowed layer's mutation is an empty oracle regardless of its count. **WORKED NOTE — THE SHADOWING LAYER NEED NOT BE A DESIGNED GATE.** `GEN-013`'s shadow was a real gate answering first; the shape is wider than that, and an INCIDENTAL constraint shadows just as completely. `GEN-025` hit it twice in one file: a pre-check added for speed (`IS NOT DISTINCT FROM`) answered before the unique index, so a broken `NULLS NOT DISTINCT` still passed; and in the race test both writers used the SAME row id, so the act collided on its own PRIMARY KEY and the probe passed with the idempotency mechanism deleted — the act was serialising itself. `GEN-027` met the same shape from the other side: the derived idempotency key answers before the provisioning predicate, so that predicate cannot be tested through the route at all and is tested at the module instead. **CONSTRUCT THE PROBE SO THE MECHANISM UNDER TEST IS THE ONLY THING THAT CAN PRODUCE THE OBSERVED OUTCOME** — per-attempt row ids, distinct keys, a fresh subject per case — and when something else must answer first, test the decision at the layer that makes it. **AND THE MUTATION ITSELF CAN BE SHADOWED:** `GEN-027`'s first attempt to weaken the zero-ever predicate left every test green, because the weakened SQL still matched an open version-1 row — the mutation was wrong, not the test, and only checking why the green appeared distinguished the two. **Distinguished from `[teardown-isolation]` by** what fails: here the **assertion has no teeth** — a mutation survives green — where there the **fixture or shared state is corrupted**, producing false breakage or a leaked pass. Two failure modes of test integrity: what a test *proves* versus what it *sets up and tears down*.
- `[teardown-isolation]` **A test's teardown deletes what that test created, never what its pattern happens to match.** A prefix chosen for convenience will one day match seed data, and the damage surfaces as a *later* assertion failing — a fixture fault wearing the costume of a code fault. `GEN-014` deleted `contact_id LIKE 'ctc_%'` and destroyed the seeded estate contacts, which presented as a domain rule failing to find a conflict that should have existed. Scope teardown to ids the test itself minted, and prefer a shape the seed cannot produce. **Distinguished from `[shadowed-layer-empty-oracle]` by** what fails: here the **fixture or shared state is corrupted**, where there the **assertion has no teeth**. This one breaks other tests; that one lets its own pass mean nothing.
- `[a-bite-is-a-named-red]` **A bite is proven by a NAMED red, never by a non-zero exit.** A mutation certifies a guard only when three things hold together: the mutation APPLIED, the suite actually RAN, and THE NAMED CASE is the one that failed. An exit status collapses all three into one bit, and every way of failing to test the guard — a compile error, a filter that matched nothing, a missing fixture, a database that was down — produces exactly the same bit as the guard biting. `GEN-044` reported **five** guards as proven that had proven nothing: the mutations used `false && <condition>`, which breaks TypeScript's narrowing, so the build failed, the suite never ran, and the harness counted the non-zero exit as the red. It was found only because somebody noticed a bite's log file did not exist. The same PID also found `${2:+--test-name-pattern="$2"}` splitting on the space inside a test name, so every filter silently ran the whole file. **State which case must go red, then require that case by name.** Where the guard is the type system the named failure is a diagnostic code rather than a case, and the rule is unchanged: name it, and require the build to break for it. `GEN-046` made the criterion executable — `docs/governance/mutations/manifest.json` records every bite with the case it must red, and `run-mutations.mjs` refuses to call anything proven on an exit status alone. **Distinguished from `[probe-must-bite]` by** what is unproven: there the guard was never shown capable of failing at all; here it failed, and the failure was somebody else's.

- `[a-bite-that-cannot-be-rerun-is-a-claim]` **A bite that exists only in prose is a claim, not a check.** A mutation run once in an interactive shell and written up in a report proves the guard bit *that afternoon, against that tree*. It cannot answer whether the guard still bites, and when a defect is later found in the harness itself there is no way to ask the same question of everything already "proven". `GEN-046` measured the corpus and found **no** script or test referenced `with-mutation.sh` at all: every bite across nine PIDs lived only in prose, so `GEN-044`'s discovery that five bites were false could not be checked against the rest. **Record the mutation as an artifact — subject, from, to, and the case that must red — so the sweep is a command and not an archaeology exercise.** The sweep pays for itself immediately: re-running `GEN-044`'s recorded case-4 bite showed the mutation (`any-node floor`) was indistinguishable from the rule it was meant to break, because a ticket addresses exactly ONE node. **Distinguished from `[a-bite-is-a-named-red]` by** what is missing: there the verdict was wrong; here there is no verdict to check.

- `[a-race-is-not-a-bite]` **A red that depends on timing certifies nothing.** A concurrency bite that fires two operations and hopes they overlap proves the guard only on the runs where they did — and nothing in the verdict says which runs those were. `GEN-040`'s publish-lock bite reddened 6/6 when its case ran alone and one run in three as the whole file, because after fifteen preceding tests the two publishes serialised naturally; `GEN-046`'s rule 4 (run the whole file, so collateral is visible) exposed it, and `GEN-047` carried it as `unreliable` rather than as proof. **Force the interleaving, or make the database hold the invariant.** Two connections and an open transaction order the steps by code: A writes and HOLDS, B runs the real act and must BLOCK on the constraint, A commits, B is refused. Or the invariant is a UNIQUE index and the bite is a constraint violation, which cannot be won or lost. `GEN-049` found the lock had guarded nothing `notice_version_unique` did not, and replaced the race with the constraint's own refusal. **Distinguished from `[a-bite-is-a-named-red]` by** what is wrong with the verdict: there the failure was somebody else's; here it is genuinely the guard's, some of the time — which is the same as never.

- `[a-live-process-is-never-piped-into-a-short-circuit-reader]` **A live process is never piped into a reader that can close the pipe early.** `grep -q`, `grep -m`, `head`, and any consumer that exits on a match or a line count closes its end of the pipe the moment it is done; the producer's next write gets SIGPIPE, and a producer that installs its own SIGPIPE handling — node's test runner, the Flutter tool — CRASHES instead of stopping cleanly. `GEN-053` D4 found it killing `node --test` before its teardown (the duplicate a dropped constraint admitted then survived); `GEN-048` F4 found it AGAIN, in the Flutter pin assertion written to satisfy F2 — `flutter --version --machine | grep -q` crashed flutter writing to stdout, a red that had nothing to do with the pin. Two strikes, one rule: **capture first, match after** — `out=$(producer)` then match `$out`, or write a file and grep the file. A captured string piped into `grep` is safe (the producer already exited); only a LIVE process must not be. **Distinguished from `[a-race-is-not-a-bite]` by** what breaks: there timing made a red unreliable; here the pipe's early close makes the producer crash, deterministically, every time.
- `[a-parser-that-cannot-read-the-result-must-not-report-one]` **A parser that cannot read the result must not invent one.** An extractor that fails to parse its input and then emits a verdict anyway is worse than one that crashes: it reports with full confidence. `GEN-048`'s app-suite gate matched only node's `spec` reporter (`ℹ pass N`); on CI, which emits `tap` (`# pass N`), it matched nothing and reported two GREEN suites as **"did not run"** — and the same dead extractor would have reported a RED suite as green. The fix distinguishes three states and never conflates the last two: counts read; the suite RAN (a duration or a tests line proves it) but the counts are unreadable, which is an **EXTRACTOR error, named as ours**; and no sign of a run at all, which is the suite's. **When you cannot read the answer, say you cannot read it — never guess the answer.** **The base-ref arm (`GEN-048` F3):** a guard whose verdict is computed against a base — `git merge-base HEAD origin/main` — must first check the base EXISTS, and if it does not (a shallow CI checkout omits `origin/main`), red as a NAMED HARNESS error, never let a raw `child_process` throw read as the guard's own verdict. The test named "not vacuous" became its own counter-example on the runner: it could not see its base and reported a numbering violation. Its sibling in the inline-shell class is the `tr` operand beginning with a space that the runner's coreutils read as an option (`[sql-literals-hold-only-sql]`'s cousin): the same afternoon, in the same battery. **Distinguished from `[a-bite-is-a-named-red]` by** where the failure is: there the guard did not fire; here the reader of the guard's result misread it.
- `[a-push-is-a-finished-tree]` **A worktree with an operation in progress has nothing to push.** Mid-rebase, mid-merge, mid-cherry-pick, HEAD is a replay position and the index may carry conflict markers that a later `commit` would keep; a push from there publishes a tree nobody reviewed and that git itself does not yet call a commit. `GEN-053` made the pre-push hook refuse while `rebase-merge`, `rebase-apply`, `MERGE_HEAD`, `CHERRY_PICK_HEAD` or `REVERT_HEAD` exists, naming which. Finish or abort; there is no third state. **Distinguished from `[merge-gate-precondition]` by** what is gated: there the CHECK's exit status; here the tree's own state before any check runs.
- `[the-track-that-owns-the-file-writes-the-line]` **When one track's change moves another track's claim, the owning track writes the adaptation ON THE CHANGING TRACK'S BRANCH.** Two rulings are both right — no track edits the other's files, and no merge passes a red gate — and under both a corpus change that moves a UI claim could never land. `GEN-052` recorded the `notice-incomplete-translation` fixture that `UI-051` had declared absent; the UI's prover reddened the gate, correctly, and the step ruling resolved it as a JOINT LANDING: UI CC committed the one-line adaptation onto `codex/gen-052`, tagged `[GEN-052]`, author recorded in the PID's report; Main CC fast-forwarded and merged through the hook. Limited to the reds the hook names; the gate is never bypassed; there is no ordering cycle. **Distinguished from `[server-owns-data-client-owns-look]` by** what is divided: there the responsibility for a field; here the authorship of a line.

- `[a-rebuild-that-keeps-node_modules-is-not-from-nothing]` **A rebuild is from nothing only if it keeps nothing.** `prove.sh`'s from-nothing rebuild dropped the schemas and rebuilt `dist/`, and kept `node_modules` — and CI, which keeps nothing, was red on every push from the first `@pemo/notices` import in `apps/api` to run #93 while every local report said "from-nothing rebuild green". The cause was a missing tsconfig reference that every local build supplied by building the modules in a loop first. `GEN-048` gave the battery a `--clean` lane that removes every `node_modules`, reinstalls from the frozen lockfile and builds as CI builds, and a guard that reds when an import is undeclared or a declaration unreferenced.
- `[guard-remedies-are-non-destructive]` **A guard's prescribed remedy may never destroy the work that tripped it.** A check speaks with the authority of the process, and the remedy it prints is followed by someone who has just been told they are wrong — so a remedy that discards uncommitted work will be obeyed. `GEN-044`'s battery pre-flight blocked the PID and prescribed *"restore it from `origin/main`"* — which would have thrown away the entire PID's work, because the check derived its victims from the tree and the PID's own new files looked like contamination. **Prescribe the narrowest reversal that clears the violation, and name the thing to be reverted rather than a branch to be reset to.** Where the guard cannot identify a safe remedy it must say what is wrong and stop, which is always better than a confident destructive instruction. This is `[destructive-target-confirmed]` pointed at the guards themselves: the same rule that forbids addressing a database by hand forbids a check from telling somebody else to. **Distinguished from `[a-check-fails-for-its-own-rules-reason]` by** which half is wrong: there the guard fired for the wrong reason; here it fired correctly and the CURE was the damage.

## On data and the world

- `[frozen-axis]` **Frozen-axis.** A hand-written list cannot grow when the world grows. Derive the axis from the world (floors → units), never transcribe it; a literal list is correct only for the size it was written at. (This applies to a PID's own coverage list: `DOC-002` caught `resident-portal` missing from a hand-listed set.)
- `[seed-from-declared-basis]` **Seed from a declared basis, reproducible from nothing.** The total is computed from the basis (`812 = 8×35 + 7×22 + 9×42`), never typed. A number the seed computes cannot be nudged to make a fixture pass. **Verify by building a fresh database from migrations + seeds alone** — and mean it: the first build's resident seed reproduced, but its management scenario seeds did not, and the test only checked the file was present.
- `[chase-the-discrepancy]` **Chase the discrepancy; do not smooth it.** A count that comes back one off is information about the basis. `DOC-002` found floors at 36/23/43, one more per block than expected; the extra was `G/F` holding only parking/storage — the discrepancy explained the model rather than breaking it. Smoothing it would have hidden a correct fact.
- `[no-coincidental-collision]` **No coincidental collision — of NUMBERS.** (The subject is numeric coincidence, not key or concurrency collision; the id has misled twice and is permanent, so the scope is stated here instead.) A generated magnitude must not accidentally equal an unrelated corpus figure; check the count against the set of known figures, or a wrong number will read as a right one.
- `[attestation-and-act-atomic]` **A record written in a different transaction from the act it attests can survive that act's failure and assert a falsehood.** Its failure mode is not absence but confident wrongness, which is worse: an audit that is merely missing is visibly missing, while one asserting an authorised act that never happened is indistinguishable from a true record. An attestation and the thing it attests are atomic, or the attestation is a liability. `GEN-009` produced 0 act rows and 1 audit row by injecting a failure after both writes, because each module's pool carried its own `search_path` and therefore its own transaction.
- `[genesis-exempt-from-idempotency]` **A GENESIS act — one with no acting principal, because it is what creates the first authority — declares idempotency EXEMPT WITH A STATED REASON, and gets its exactly-once from an append-only EXISTENCE GUARD evaluated FIRST, under the entity lock.** The ordinary mechanism cannot apply: `ADR-015` `D3` keys on `(principal, operation, key)` and a genesis act has no principal to key on. Declaring `exempt` is not a shrug — `ADR-015` `D1` requires a stance and refuses an undeclared operation, so the reason is the deliverable: *exactly-once is guaranteed instead by X*. In `GEN-032` X is **zero grants EVER** over `access.scope_grant`, which is append-only — so an ended grant's assertion still exists and still bites, and an organization cannot revoke its way back to a genesis act. **That is STRICTLY STRONGER than a key table**, which only remembers keys it was given. **THE TENSE IS THE WHOLE GUARD, AND IT IS EASY TO GET BACKWARDS:** a *currently holds none* predicate re-opens the act to anyone the moment the last grant ends, which is the standing break-glass `ADR-010` `A1` forbids, reached by an ordinary revocation rather than a back door. **And ORDER is load-bearing** — the guard runs before the first INSERT, or a refused second attempt leaves the orphans of its own writes. **Distinguished from `[attestation-and-act-atomic]` by** what is being secured: there that a record and its act commit together; here that an act with no actor can happen at most once in the lifetime of the thing it creates. **And distinguished from `[unrepresentable-over-forbidden]` by** where the impossibility lives: there in the schema's shape; here in a predicate over history, because the state being forbidden — *a second genesis* — is not a row but the absence of every row.
- `[diff-against-clean-baseline]` **After any operation that touches the tree, diff against a known-clean baseline.** Pin drift and stray staged trees are invisible until something reads across; the diff is what makes them visible.

- `[assert-the-isolation-level]` **A guard that depends on an isolation level asserts it rather than trusting the default.** Correctness that rests on an ambient setting fails silently the day the setting differs, and the code looks identical while guarding nothing. `GEN-016`'s advisory-lock guard serialises check-and-append **only** under `READ COMMITTED`, where each statement takes a fresh snapshot; under `REPEATABLE READ` the blocked writer would not see the winner's committed row and would append anyway. The guard reads `SHOW transaction_isolation` and refuses with a named reason. **Name the ambient condition your correctness rests on, and check it.** **Distinguished from `[context-inherited-env]` by** whose ambience: here the **database session's configuration**, which the code can read and refuse on; there the **process environment inherited from the caller**, which differs by invocation context and is controlled by stripping it rather than by asserting it.

## On boundaries and homes

- `[partition-by-what-it-determines]` **Partition by what an artifact determines, not where it lives.** Two concerns in one file are classified per concern; the classifier is then load-bearing and needs its own test.
- `[decision-has-one-home]` **A decision must have one home.** Two copies of a decision with nothing deciding which is real is a defect. A `(1).md`, a second table row, or a reused number (two `NNN` files in one directory) is an alarm, not a convenience — a single global sequence, no type prefix resets it, and a number once allocated is never reissued.
- `[merge-and-close-are-two-acts]` **Merging a PID and closing it in the register are two acts.** Releasing the commit orders the merge and nothing else; the close — archive move, status stamp, artifact carry — is its own instruction, given explicitly every time. `GEN-006` was merged in fact and `draft` in the register for three commits because its ruling released the commit and never ordered the close.
- `[destructive-target-confirmed]` **A destructive operation confirms the real target it will act on, never a label that claims what the target is.** The same misconfiguration that points it at the wrong target can set the label too: a correct `PEMO_ENV=development` beside a connection string pasted from staging passes every label check and drops the wrong database. Check the connection target — dbname and host — and treat the label as the cheap extra. Read-the-artifact-not-the-summary, applied where being wrong destroys rather than misleads. **And the confirmation must be a pure-configuration check that runs BEFORE anything reaches the network** — a guard sitting downstream of a reachability probe is bypassable, because a wrong target that happens to be unreachable short-circuits into a skip and the guard never executes. `GEN-008` shipped exactly that: both of its reds "fired" green, and the tell was that neither refusal message ever appeared. A safety check a bad target can route around is not a safety check.
- `[unrepresentable-over-forbidden]` **Prefer unrepresentable over forbidden.** Make the bad state impossible to express rather than forbidden by a rule someone can forget. A `NOT NULL` beats a comment saying "do not leave this blank".
- `[delegation-floor]` **YOU CANNOT CAUSE AUTHORITY YOU CANNOT YOURSELF CONFER.** A gate written for a single grant does not cover an act that confers a SET of them. The floor for a change is effective `grant_administrator` covering **every node the change could cause the subject to hold authority at** — a **conjunction** over that set, never a subset, because there is no partial version of the act to admit. `ADR-010` `D3`'s `G-2` gates a grant at the one node it names; `ADR-017` lifts it to the set, because adding a member to a group hands them the union of the group's live grants in one act with no per-grant decision. Without the lift, an administrator at one building could add themselves to the group holding `grant_administrator` at the organization and inherit everything. **AND THE EMPTY SET IS THE TRAP:** a conjunction over no nodes is *vacuously true*, so a group conferring nothing today would admit anybody — and that is PRE-STAGING rather than a harmless no-op, because the caller inherits whatever a legitimate administrator later confers, and the conferrer's own gate looks at the NODE and never enumerates members, so nothing downstream catches it. `GEN-033` closes it by requiring the ORGANIZATION node for a grantless group — the strongest floor for the case that confers least today and could confer anything tomorrow. **EFFECTIVE, NOT MERELY GRANTED:** the authority that satisfies a floor is the `GEN-030` witness — a live grant AND a live membership — because a grant held by a group with no members is an administrator who does not exist. **Distinguished from `[unrepresentable-over-forbidden]` by** where the limit lives: there a state is made impossible to express; here a state is perfectly expressible and the question is whether THIS caller may bring it about. **And distinguished from `[audience-boundary-unconditional]` by** what is being decided: there whether a surface may show something at all; here whether an actor may cause someone else to hold something.
- `[authority-owns-its-precondition]` **A gate must own the condition it is gating on, not receive it as a promise.** A parameter typed as the REPRESENTATION of a decision — a flat `readonly string[]` of node keys — accepts a value that was never filtered as readily as one that was, so the guard's correctness moves out of the guard and into every caller. It reads as safe for exactly as long as every caller happens to be right. `ADR-010` `D3`'s `G-2` took such a set for three PIDs; every route did filter it to `grant_administrator` grants, and `GEN-033` carried the hole out at close because **EXPANSION DISCARDS THE ROLE**: a `ScopeGrant` knows it is `estate_staff`, a node key does not, so once flattened an administrator scope and a staff scope are the same type and a route passing its full expanded scope would have widened every floor from *administers this node* to *holds any grant anywhere*, silently. `ADR-018` closes it by giving the value a **branded type with one constructor** that applies the predicate itself, so the caller cannot skip the filter: it never sees the filtered list. **The two halves fail differently and need two proofs** — that a raw value cannot reach the gate (a COMPILE, since a type-stripping test runner sees no type error at all), and that the one constructor filters correctly (a RUNTIME check, because a type guaranteeing where a value came from says nothing about whether that place is right). **Distinguished from `[unrepresentable-over-forbidden]` by** what is made impossible: there an invalid STATE cannot be written down; here a valid state is reachable only through the one act that establishes its precondition. **And distinguished from `[delegation-floor]` by** layer: that names WHAT the floor must be, this names WHO is answerable for the floor's inputs being true.
- `[audience-boundary-unconditional]` **The audience boundary is unconditional, and it must be tested on what the server emits, not on the registry.** A resident-only problem type reaching the management surface is a boundary breach; the check must assert the running surface never emits a type marked for the other audience — `DOC-002` found the global 404 leaking `event-not-found` onto `/management/*` with the contract suite green over it.
- `[tests-run-from-clean-export]` **Software tests must run from a clean export.** A test that asserts repository state (shells out to `git`) or depends on a working-copy artifact is un-runnable in CI, containers, or an audit export. Assert the software's behaviour, not the governance process; keep the latter in a separate lint that runs where `.git` exists.
- `[rulebook-has-a-scope]` **This rulebook has a scope.** It was built for sessions that merge into a shared repository, and applying it to a session that does not merge — a design hand, a read-only audit — imposes cost with no defect prevented. Before requiring a protocol of a session, name the disaster it prevents FOR THAT SESSION; if you cannot, it does not apply. A day of two design sessions was spent on register mechanics and filesystem forensics that could not have protected anything they do.
- `[reference-do-not-absorb]` **Reference what you do not own; do not absorb it.** PEMO references the car park, the fire consultant's attestation, lift statutory compliance — it does not become their register. The boundary is the same shape each time.

- `[constraint-violation-never-500]` **A database constraint doing its job is not a server fault.** A raw `23505` or serialization failure reaching the client reports an internal error for an act the system correctly refused. Map it to the act's **truthful outcome** — the winning act's answer, which is what the losing racer should also see. `GEN-016` found this by removing the advisory lock: `UNIQUE (occupancy_id, version)` bit exactly as designed and surfaced unmapped, so a correctly-refused end read as a `500`. It now answers *the instance is already ended → not live → 409*, with nothing appended. `ADR-013` `C4`.
- `[sql-literals-hold-only-sql]` **A SQL template literal contains only SQL.** Explanation, rationale and comments live in the host language, outside the literal. Prose inside a query string is executed as part of it, and every escaping rule of BOTH languages applies at once — so an apostrophe, a backtick or a backslash written for a human changes what the database is asked. `GEN-041` hit this twice in one function, **both times in prose about escaping**: a backtick inside a `--` comment terminated the template literal and the identifiers after it became JavaScript (`ReferenceError: occurred_at is not defined`), and the replacement comment then had `\n` become a REAL NEWLINE, splitting the comment and leaving a bare `and` in the query (`syntax error at or near "and"`). Neither is a typo you can see by reading the line; both compiled cleanly. The class had already been recorded three times over (`_` as a LIKE wildcard, `\n` in a mutation string, `\d` in a computed RegExp) before it was given a rule. **Distinguished from `[anchor-the-discriminator]` by** what goes wrong: there a pattern matched the wrong THING; here the string is not the string you wrote. `GEN-042` swept the repository and moved 10 such lines into host-language comments.
- `[adapter-bite-severs-the-plumbing]` **A thin adapter is proven only by the mutation that severs it from what it adapts.** A route, a port, a wiring shim contains almost no logic — which is exactly why a test of one is so easily vacuous. Asserting a status code, a version that advanced, or that nothing threw exercises the CALL and never the CONNECTION, so an adapter that drops its input, its scope, or the call itself still passes. **The bite is: make the adapter ignore its input** — the request body, the path parameter, the caller's scope — and require the test to red. `GEN-042` shipped `revise` and `correct` passing an EMPTY content object: the version advanced, the change was silently discarded, and the route tests were green because they asserted the version had moved. `GEN-043` restored the missing mutation across all fifteen routes. The same shape applies to a READ adapter, where the severed thing is the scope: a projection handed the caller's node keys and ignoring them returns everything and passes any test that only checks the rows it expected are present. **Distinguished from `[mutate-to-the-plausible-wrong-rule]` by** what is mutated: there the RULE is replaced with a plausible wrong one; here the adapter is disconnected from the rule entirely, which no change to the rule can detect.
- `[correlated-lists-certify-nothing]` **Two hand-kept lists that agree certify nothing.** A check whose EXPECTATION and whose SUBJECT derive from the same hand-maintained source confirms the source, not reality — and it does so while looking exactly like a passing check, which is why it survives review. `GEN-037` measured it: `010-grants.sql` granted over a hand-kept schema array and `grants-complete.sh` filtered by an identical one; both omitted `notices`, so the schema was created, migrated and seeded with `pemo_app` holding **no privilege on it at all** while the check reported `ok — 44 tables, SELECT+INSERT only`. It was green over a schema the application could not read, because a check that validates the grants which EXIST cannot see a schema absent from its own list. **DERIVE AT LEAST ONE SIDE FROM GROUND TRUTH** — the database, the filesystem, the type — so the two sides can disagree. Where a declaration must stay hand-written because it records a DECISION, keep exactly one and have it compared against reality: `GEN-039` reduced five copies of the module list to one declaration plus an inventory test that checks it against the schemas that actually exist. **Distinguished from `[patch-verify-on-disk]` by** whose word is being taken: there a TOOL's self-report stood in for its effect; here the measurement really happened, against a yardstick cut from the same cloth as the thing measured.
- `[the-exception-that-proves-the-rule-is-where-the-rule-fails]` **A gate skipped on the judgement that this change is too small or too narrow to need it is precisely the change that breaks it.** A discipline does not die by disagreement — no one argues the gate is wrong — it dies by a this-one-is-different: the full check is run for every change except the one judged not to need it, and that judgement is made most confidently exactly where it is most wrong. `GEN-056` established, one PID earlier (`GEN-055`), that CI's full register set must be run locally before pushing, because three CI-only surprises had proven the local gate saw less than CI. Then it judged its own change "Dart-only" and ran the stamp check and `run-mutations` alone — and CI caught two failures (a debt-coupled gate test and a corpus-render gap) the full local run would have surfaced. **Run the whole gate on every change; a change that seems too small to need it is the case selecting itself for the exception that fails.** **Distinguished from `[a-gate-that-runs-less-than-CI-is-not-the-gate-it-claims-to-be]` by** which link breaks: there the GATE covered less than CI by construction; here the gate covered enough and was SKIPPED by a judgement call.
- `[a-consumer-outside-the-stamp-check-is-not-a-consumer-it-is-a-copy]` **A generated consumer the stamp check does not walk is not a consumer — it is a copy that drifts unseen.** GEN-046 ruled that the PID which bumps a contract regenerates EVERY consumer, and built a check to enforce it — but the check walked only `apps/<app>/src` for `*.g.ts`. The Flutter app's `severity_tokens.g.dart` and `fixture_corpus.g.dart` live under `lib/` and are `.g.dart`, so they were outside the walk; `resident-mobile/severity.json` moved 0.2.2 → 0.4.0 across GEN-042 and GEN-052 and the Dart consumers stamped 0.2.2 for a month, caught only when GEN-048's Flutter gate finally RAN the contract test. A rule enforced by a check that cannot see part of what it governs is enforced nowhere for that part. **The remedy is the check's REACH, derived: walk every generated file — every language, every directory a consumer can live in — and let each name its own source and stamp, so a new consumer is covered by existing and a new language needs one branch, not a new list.** GEN-056 extended it to `.g.dart` under `lib/`, keeping the discovery derived (`[correlated-lists-certify-nothing]`): the file type, the source contract, and the version stamp are all read from the file, never enumerated. **Distinguished from `[correlated-lists-certify-nothing]` by** where the omission hides: there a hand-kept LIST left out the stale item; here the check's WALK did not reach the language the stale item was written in — a list can be audited by reading it, but a walk's blind spot is invisible until something in it drifts.
- `[a-check-fails-for-its-own-rules-reason]` **A guard must fail only for a violation of the rule it serves.** *Instance (`GEN-052`, class recorded at `GEN-053` D3): a DDL `CHECK` is the LAST line, never the first — an act must refuse with the declared Problem before the row reaches it, or the constraint fires for its own reason and the caller sees a 500, which is nobody's reason. `notice_schedule_ordered` was the first found, at `INSERT` of a draft.* A check that reds for a neighbouring rule's reason teaches people that its failures are noise, and the remedy they learn is to widen the allowlist — which is how a guard is disarmed by the people maintaining it, one reasonable exception at a time. `GEN-038` dropped the whole `instrument` group (lease, deed, mortgagee, land registry) from the `service_case` denylist for exactly this reason: those terms mark `ADR-011`'s tenancy boundary, so a hit in `service_case` would have been catching an `ADR-011` violation in a schema `ADR-011`'s own scan does not cover. Keeping them would have made the list assert a boundary it is not the guard for. If the terms should be corpus-wide, that is a scan-scope extension of the rule that owns them, never a re-add here. **Its test-side dual is `[mutate-to-the-plausible-wrong-rule]`:** a bite that reds for a neighbouring constraint's reason is not a bite — `GEN-038` found a supersession test that passed while the supersession constraint was dropped, because a reused `assertion_id` meant the PRIMARY KEY was refusing the duplicate. `GEN-039` `G2` applied that retroactively to every assertion table. **Distinguished from `[audience-boundary-unconditional]` by** what is at stake: there a surface must not emit something; here a guard must not fail for the wrong reason.
- `[merge-gate-precondition]` **A gate is what the push is conditional on, not what the executor remembers to run.** A check whose exit status nothing branches on is not a gate. `GEN-013` pushed a register that failed `pid-index --check` because the shell chain gated the push on the **commit** succeeding rather than on the generator; CI would have caught it only after it landed, which is the wrong side of the boundary. The same class as trusting a build's success without reading its status. **Make the gate refuse, and prove it refuses by breaking something on purpose.** **Distinguished from `[patch-verify-on-disk]` by** the fix: here the gate was wired to the **wrong exit status**, where there a tool's **self-report** was taken as evidence of its effect.
- `[a-guard-that-matches-text-without-its-context-reds-for-someone-elses-reason]` **A guard that matches text without its context reds for someone else's reason.** A pattern that fires on a token wherever it appears — a schema name, a banned word, a verb — flags every innocent occurrence that shares the spelling, and it does so in a file whose author has no idea the guard exists. `GEN-059`: the `no-cross-schema-sql` scanner extracted string literals carrying a SQL verb and matched `\b<schema>\.<ident>`, but read a template literal's `${...}` interpolation as string content. `apps/management-web/tool/live-exercise.ts` printed `` `…${l.data.notices.length}… from this run` `` — a log line running no SQL — and the interpolated `notices.length` (a JS property access; `notices` is also a schema) plus the English word "from" made it a "cross-schema statement". It reddened UI-054's merge for a Main-track guard, on a file the UI author never suspected. **The fix is to require the token's CONTEXT, not to enumerate more forbidden spellings: read the qualified name and its verb from the STATIC text of the literal — the authored SQL skeleton — never from a value spliced in at runtime.** The sweep found the guard was carrying exactly one false positive of this class (the one that fired) and no others latent. **The precision fix must bite BOTH ways:** a real crossing still reds AND the innocent line no longer does — because a guard can always be made "precise" by disabling it, and only the first bite catches that. **Distinguished from `[anchor-the-discriminator]` by** where the looseness lives: there the pattern was unanchored (a substring matched a bigger word); here the pattern was anchored correctly but pointed at the wrong TEXT (a runtime value, not the SQL). **And the cross-track cost is the point:** a guard that reds for someone else's reason is worst when the someone is on the other track, with no way to see why.

## On concurrency and time

- `[a-suite-whose-verdict-depends-on-file-order-certifies-nothing]` **A suite whose verdict depends on file order certifies nothing.** `node --test file1 file2 …` runs the files in the glob's order, which is the filesystem's — different between machines and runs — and every file shares one database. So a teardown that deletes less than its setup created, or reaches past its own fixtures, leaves residue whose effect on a later file depends on which ran first. `GEN-048` shipped green on a branch and red on `main` at the SAME commit for exactly this: `membership-assertions` created a `_w3r` and a `_w3g` fixture family and deleted only the `_w3g` half, so under some orders the surviving `_w3r` grant's foreign key choked a later broad delete. **Run the suite in a DECLARED order (sorted), and prove order-INDEPENDENCE by running it under shuffled seeds and repeated on one un-reset database — order-independence holds only when every teardown owns exactly what it created.** `GEN-057` built `run-integration.mjs` for the declared order and the repeated-run proof, and it was the repeated run — not any single pass — that surfaced the defect below. **Distinguished from `[correlated-lists-certify-nothing]` by** what the false green rests on: there a check measured against a yardstick cut from its own cloth; here a test passed because the filesystem happened to order the files kindly that run.

- `[a-lock-that-serialises-visibility-is-defeated-by-a-clock-frozen-before-the-wait]` **A lock that serialises visibility is defeated by a clock frozen before the wait.** An advisory lock makes the loser block until the winner commits and then read the winner's committed row — but a liveness predicate on `now()` (`transaction_timestamp()`, fixed at the loser's transaction START) evaluates "is it live" as of a clock from BEFORE the loser waited, so a grant the winner revoked while the loser was blocked (its `effective_to` stamped after that frozen instant) still counts as live. `GEN-057` measured it as a reachable **zero-administrator lockout**: `revokeGrant` and `removeMembership` both took the organization lock correctly and serialised (the loser blocked ~213 ms), yet both read two witnesses and committed — the exact GEN-030 unrecoverable state the lock exists to prevent — because `EFFECTIVE_ADMINISTRATORS` filtered on `now()`. The lock had done its job; the clock undid it. Sufficient ONLY under READ COMMITTED (measured on every path here), where each statement re-snapshots; under a snapshot-stable level the frozen SNAPSHOT, not the clock, is the problem, and the remedy is retry-on-serialization-failure or a fresh transaction. `ADR-017` / `GEN-030`. **Its remedy is `[a-guard-that-reads-after-waiting-must-read-at-the-time-it-waited-until]`.**

- `[a-guard-that-reads-after-waiting-must-read-at-the-time-it-waited-until]` **A guard that reads after waiting must read at the time it waited until.** The purpose of blocking on a lock is to read a world the winner has already changed; a predicate that reads liveness at the transaction's start throws that purpose away. Under READ COMMITTED, read every post-lock liveness predicate with `clock_timestamp()` (the wall clock at THIS statement), never `now()`/`transaction_timestamp()`/`CURRENT_TIMESTAMP` (frozen at the transaction start). `GEN-057` swept seven such predicates across `access` and `resident` — the last-administrator guard, the delegation floor, and the confer/add/occupancy conflict reads — every one reached only after a serialising lock. The bite is deterministic and needs no race: in one transaction, supersede an instance to expire at `now() + Δ`, sleep past `Δ`, then call the guard — under `now()` the expired row still counts, under `clock_timestamp()` it is gone. **Distinguished from `[constraint-violation-never-500]` by** where the race is decided: there the database's own constraint refused the loser and the fix was to map its error truthfully; here the application's own guard admitted the loser and the fix is to read liveness at the right clock.

## On the twist between tiers

- `[server-owns-data-client-owns-look]` **The app-server owns "what and whose data"; the front-end owns "how it looks".** Authorization and derivation — filtering in-query, scope, severity level, computed counts — are the server's, because out-of-scope data must be *absent from the response body*, not hidden client-side, and the audience boundary is unconditional. Presentation — layout, formatting, i18n, composing already-authorized fields — is the client's, so UI can change without a backend deploy. The contract sits at the seam and moves only for new authorized data, never for presentation churn. A client-side "twist" that filters or derives safety-relevant data is a boundary breach wearing a convenience hat.
- `[a-surface-that-displays-without-a-source-is-a-drawing]` **A control that offers a choice no read consumes, and a number whose definition no server owns, are the same failure — a drawing, not software.** They are indistinguishable from working software at a glance and distinguishable only when someone acts on them. The remedy is never to remove the affordance and never to make the client compute the missing half; it is to give the surface a source. `GEN-064` found the management-web Overview shipped this way: a scope `<select>` with no `onChange` whose value nothing reads (`Shell.tsx:152`), and four counter tiles whose numbers were fixture literals no server computed (no `getOverview` route), rendered identically under `source=live`. It is the sibling of `[server-owns-data-client-owns-look]` seen from the client side, and of `[correlated-lists-certify-nothing]`: something *looks* like the thing it stands for and is not it. **The corollary — the server counts, the client never counts — is G7 in a second setting:** a counter and the list it links to are produced by ONE server-side definition evaluated once per scope — never a badge the client derives from a list it holds, which is the click-31-see-28 trap, a shape testing cannot rule out once two definitions exist. `basis` (what the count claims about itself) is derived from the applied definition, not typed beside it.
- `[absence-is-not-zero]` **A quantity we cannot compute is omitted, not rendered as nought.** A response array keyed by an enum need not carry every key; a counter the server cannot source is left out entirely, and the client draws nothing where the key is absent — as though it were never in the vocabulary. This is G7's shape in a third setting (the server omits, the client never draws a placeholder): a tile reading `0` claims there are no such things; a greyed tile claims we know the number and are withholding it. Both are lies, and the second is the costlier because it looks like a feature. `GEN-064` omits `open-cases` from `OverviewResponse.counters` because a case carries no scope it can be counted by (`[provenance-is-not-a-join]`); UI-065 draws no tile where a key is absent. Corollary to `[a-surface-that-displays-without-a-source-is-a-drawing]`.
- `[count-the-thing-not-the-rows-that-mention-it]` **A count is over distinct subjects, never over the join rows that reference them.** A fan-out table lists one subject once per related row; counting those rows reports one estate-wide event as thirty. `GEN-064`'s `safety-events-window` counts DISTINCT `event_id` over `safety_event_audience` (which fans one event across every unit in its audience), and its list returns each event once with the audience intersection as an attribute, never as row multiplicity — with `retracted = false` on both the count and the list, since a retracted event that keeps counting is a safety surface reporting a withdrawn incident. A count re-derived by hand from an artifact is one failure; this is its sibling — a count inflated by the shape of the join it was taken over.
- `[provenance-is-not-a-join]` **A reference kept to record where a thing came from does not become a structural link because a query needs one.** If a read cannot be answered without traversing it, the missing relationship is real and must be declared, not borrowed. `service_case.originating_ticket_ref` is documented as provenance only (`0138:24`); resolving a case's scope by walking it to a `helpdesk.ticket`'s node turns provenance into an undeclared foreign key — restoring at runtime the helpdesk/service-case coupling ADR-020 removed, while the schema still claims independence (worse than a declared coupling, because nothing guarantees it), and wrong at the edges the borrow ignores: a case with no ticket has no scope and vanishes from every node-scoped list; a case with two tickets at different nodes has no single scope for a one-`ScopePath` field. The contract already declares `scope` per case; the declaration is right and the schema is behind. `GEN-064` stops rather than build the borrow; a case carrying its own scope as a first-class assertion is owed an ADR-020 amendment. **Distinguished from `[a-consumer-outside-the-stamp-check-is-not-a-consumer-it-is-a-copy]` by** direction: there a real relationship is silently duplicated; here a real relationship is silently synthesised from one that was never it.
- `[a-field-with-no-authorised-source-is-removed-not-emptied]` **A response field that no authorised read can populate in ANY scope is struck from the contract, not shipped as an empty container.** The empty container is `[a-surface-that-displays-without-a-source-is-a-drawing]` moved into the schema — a declared shape indistinguishable from a feature until someone asks it for data, and a promise the server cannot keep — and it hands the UI a field it must decide whether to render, reviving the placeholder temptation. `GEN-064` found `integrationHealth[]` (integration-health reads unauthorised, need an ADR) and `attention[]` (late-arrival source is unbuilt debt) unsourced in `OverviewResponse` — but they have a live consumer (`S2Overview.tsx`), so the removal is **sequenced behind `[a-removal-needs-its-consumers-counted-first]`**: the fields STAY declared (optional; `getOverview` omits them, never fabricates them), and come out later with their consumer, in the track that owns the file, at the version that also fixes the screen. Not repealed — the field still comes out; it comes out with its screen. **Distinguished from `[absence-is-not-zero]` by** what is missing: there a value whose DEFINITION exists is absent in THIS scope and the key stays in the vocabulary; here a FIELD whose source does not exist at all leaves the vocabulary — once its consumers are counted.
- `[a-removal-needs-its-consumers-counted-first]` **A ruling to strike a declared field or surface is not sound until its consumers are enumerated.** Removal without the consumer census is a change proposed blind; the census can turn "remove it" into "coordinate its removal," and only the census tells you which. `GEN-064` Amendment 4 ruled `attention[]`/`integrationHealth[]` struck from `OverviewResponse` without the evidence that `S2Overview.tsx:70/:88` consume both — so the strike would have regenerated the types, reddened `tsc` and the browser suite, and been rejected by the pre-push hook: a backend PID cannot land a removal that reds the UI track. The census (run by the executor, not the ruling) resolved it to DEFER (Amendment 6): keep the fields optional, omit them from the sourcing route, and let the removal land with UI-065 in the track that owns the screen. **The order is: enumerate consumers, THEN decide remove-vs-coordinate — never the reverse.** Sibling of `[the-track-that-owns-the-file-writes-the-line]`: there the adaptation to a change is authored by the owning track; here the DECISION to change is gated on knowing who the owning tracks are.
- `[a-screen-that-renders-the-same-with-and-without-its-read-has-no-read]` **If deleting a screen's read leaves the screen looking identical, the screen has no read — whatever the tests say.** A fixture standing in for a live response is invisible until the response is removed and nothing changes. `GEN-064`'s Overview rendered from `mob-s2-overview/default.json` even under `source=live`, and nothing went red: the harness could not tell "the live read returned this" from "no live read happened." The acceptance test for a live surface is therefore adversarial — remove the route and require the surface to reach a visibly, testably different (failure) state — not "does it show the right numbers" (a fixture shows those too). Paired across tracks: the route lands in the data PID, the with-and-without-read distinction is proven in the screen PID.

## On reports and summaries

- `[read-the-artifact]` **Read the artifact, not the summary.** A summary and the artifact it summarises will disagree, and the summary is what propagates. Every cross-session error of this build was a summary travelling in place of the thing.
- `[stale-read-travels]` **A stale read travels as confidently as a summary.** Reading the artifact instead of the relay is only half the rule. A read taken at the moment of *investigation* and quoted at the moment of the *claim* is stale if the artifact moved between — and it carries the same false confidence as a summary. Re-read at the moment of the claim. (The `DOC-002` executor read `D01` at ~10:47, it was amended at 11:25, and the "D01 is known-wrong" claim quoted the 10:47 read; the right rule, undone by not refreshing. The check is cheap.)
- `[ruling-delivered-when-readable]` **A ruling is delivered when the recipient can read the artifact, not when it is written.** Filing and notifying are two acts; both are required, and the notification must carry a path the recipient can actually reach.
- `[absence-in-view-is-not-absence]` **Absence in your view is not absence.** Report "I enumerated X and it is not there, and I cannot see Y" — never "it does not exist" — unless you have enumerated every place it could be. A check that cannot reach a location returns silence, and silence is not a negative result.
- `[mirrors-are-append-only]` **Where a session cannot reach the authority store it holds a mirror, and mirrors are append-only.** A delivered artifact is never edited in place; a change is a new artifact with a new name. This is `ADR-003` AM4's Location-identity rule applied to documents: identity is permanent, ambiguity resolves by a new id.
- `[role-name-is-not-identity]` **A role name is not an identity.** Two sessions can answer to the same role, and an instruction addressed to the role reaches whichever one the relay happens to hit. Address a session by what it has enumerated holding, never by what it is called.
- `[enumeration-names-its-root]` **An enumeration that does not name its root is not evidence.** State the root walked and the depth — "I enumerated the project root at X, depth N", never "I enumerated my filesystem". A session correctly reported files absent from a walk that never reached the scratch directory holding them; the unqualified wording sent the Brain hunting for a session that did not exist.
- `[absence-in-set-that-did-not-arrive]` **Absence in a set that did not arrive says nothing about absence in the set as authored.** When a transfer fails, the resulting hole is a fact about the transfer, never a finding about the source. Do not report it as one, and do not let it stand in for verification you have not performed.
- `[consolidated-reissue-inherits-authority]` **A consolidated re-issue inherits the authority of the consolidation while carrying claims from the drafts it replaces.** Re-verify every load-bearing claim at the moment of consolidation, or mark it carried-unverified. A ruling propagated a false claim about global rule 7 through exactly that mechanism — the executor had already corrected it, the correction was not carried, and the consolidation lent the stale sentence fresh authority. It took a second objection from the executor to withdraw it.
- `[selective-gap-disclosure]` **Selective gap-disclosure inherits credibility for its silences.** A report that names one carried gap reads as "gaps named"; an undisclosed gap is then more hidden than if none were disclosed. When you disclose a gap, enumerate every known gap or state the list is complete.
- `[self-justifying-error-loop]` **The self-justifying-error loop.** A document recommends an action; a session acts on it and produces an artifact; the artifact is written back into the document as its next action. The document that caused the error now cites the error's own descendant as authority. Allocate from the directory (not prose), and verify status against the source before acting.
- `[carry-attribution-and-qualifier]` **Carry attribution and qualifier; decompose the claim.** "Byte-identical, all 46" travels as a fact and is usually neither. State who measured, under what qualifier, and break the claim into the parts that can each be checked. "Worth keeping" (99.6%) and "drop-in" (38%) are two different measurements of the same repo; report both, never one as the other.
