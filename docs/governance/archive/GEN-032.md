# GEN-032 — W3 batch 3b-ii: the atomic bootstrap

**The genesis act.** One transaction takes an organization from zero authority to a working
`grant_administrator`: record the principal, create the group, confer the first grant, seat the first
membership — or none of it.

**Dispatched as `W3-3b-ii`.** That id is **not usable as a PID id**: `pid-index.mjs`'s `ID_RE` is
`^(TYPE)-\d{3}$`, and a file named `W3-3b-ii.md` is not merely rejected — **the scan does not see it
at all**, so it would sit outside the allocation authority Rule 1 defines. Allocated from the
directory as `GEN-032`; `W3 batch 3b-ii` is the batch label.

## The new principle this batch defines

**`[genesis-exempt-from-idempotency]`** — a genesis act with no acting principal declares idempotency
**exempt, with a stated reason**; exactly-once is guaranteed instead by an **append-only existence
guard evaluated first, under the entity lock**.

## RULED — PID naming, so this cannot recur

**The PID id is always the `GEN-NNN` the register allocates.** Batch language (`W3`, `3b-ii`) is a
**label** — it belongs in a title or a body, **never as the id and never as the commit tag**.

The reason is worse than a format rule: `pid-index.mjs`'s `ID_RE` is `^(TYPE)-\d{3}$`, and a
`pids/` file whose stem does not match is **not rejected — it is not seen.** Probed at this PID: a
`pids/W3-3b-ii.md` file left the checker reporting `OK … Next allocation: 032`, so the file sat
outside the allocation authority Rule 1 defines, invisible to `max(NNN)+1` and to the duplicate
check.

**Owed, folded into the R5 grep-cluster PID:** the allocation checker must **FAULT** on any `pids/`
file whose stem does not match `ID_RE`, rather than silently skipping it. Until that lands, the
naming rule above is what prevents recurrence.

**Batch iii takes the register's NEXT allocation as its id** — not `W3-3b-iii`.

## Archive note — the bootstrap lands; W3 still is not finished

**What landed:** the genesis act — record the principal, create the group, confer the first grant,
seat the first membership, in **one transaction**, with the zero-grants-**EVER** guard evaluated
first under the organization lock. Idempotency **exempt with a stated reason**
(`[genesis-exempt-from-idempotency]`). Contract **`1.0.0`**, a breaking major bump under the
`ADR-008` amendment carried in here.

**What did NOT land — batch iii:**

- **`registerPrincipal` has no route**, so the second and later staff members cannot be onboarded
  through the API.
- **`addMembership` and `removeMembership` have no routes** — built and guarded at `GEN-030`, still
  unreachable.
- **The standalone-registration authority floor** is flagged, not decided.

**The DBA is gone only once batch iii lands.** An organization can now be brought into existence with
one administrator; it cannot yet be given a second person.
