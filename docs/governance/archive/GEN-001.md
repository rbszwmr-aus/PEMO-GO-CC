## What to build

The governance substrate, **in the git repository** (not G-drive), so that from here on merges and history are real. This is the fix for the first build's largest structural mistake — governance on G-drive, where history is "whoever saved last", and where a handoff package silently regressed to an older version and a reused number went unnoticed for three messages.

On branch `rewrite`, off the pinned `origin/main`:

- `docs/governance/pids/` — **one file per PID**, the source of truth for allocation and status. Each carries YAML front-matter: `id, type, version, from, to, status, pin, write_scope, reports`.
- `docs/governance/PID-INDEX.md` — **generated** from `pids/*.md` front-matter; never hand-edited.
- **The generator** — a script that scans `pids/` + `reports/` + `archive/` **once** and, from that single directory read, emits three things (it reads authority — the directory — not the restatement):
  1. the index table;
  2. the next allocation number, `max(NNN)+1`;
  3. a **duplicate-`NNN` check that fails loud**. Reference derivation (from the `DOC-002` executor):
     ```
     ls governance/pids/ reports/ archive/ | grep -oE '[A-Z]+-[0-9]{3}' | grep -v '^ADR-' \
       | sort -u | sed 's/.*-//' | sort | uniq -d
     ```
     Empty output = every `NNN` held once; any line **is** the two-files alarm, named.

  **`archive/` is in the scan deliberately.** The rule is *a number, once allocated, is never reissued* — not *a number currently visible in `pids/` is taken*. Those coincide today only by convention (rule 7 moves a closed PID's **row**, while its file stays). If a future tidy-up moved closed PID **files** to `archive/`, a scan ignoring `archive/` would lose those numbers silently: `max(NNN)+1` walks backwards and the duplicate check goes quiet **because the evidence left the directory it reads**, presenting as a clean register.
- `docs/governance/PID-PRINCIPLES.md`, `PID-TEMPLATE.md`, and the global rules — carried in from `rewrite/` on the G drive, **verbatim** (verify by round-trip: staged == committed).

Allocation is defined as creating a `pids/<ID>.md` file; `id = max(NNN)+1` over `pids/`, `reports/` and `archive/`, excluding `ADR-NNN`. **Numbers are a single global sequence; a type prefix does not reset it.** At the time of writing the staging register holds 001–004, so the next allocation is 005 — **verify this by running the generator, do not take it from this sentence.**

**Not in scope:** migrating the KEEP design docs (ADRs, function-scope, architecture, the authority spine). Those are later PIDs, numbered by the scan. This PID lands the machinery they ride on and nothing else.

## Done when

- The generator, run over `pids/`, reproduces the committed `PID-INDEX.md` **byte-for-byte** — proven by regenerating and diffing.
- A second file added at an existing `NNN` makes the generator **exit non-zero, naming the duplicate** — proven by creating one and running it. This catches the alarm **at creation**, not on a later read (the `DOC-002`/`GEN-002` collision was caught three messages late; this closes that gap).
- **A number held only in `archive/` is still refused for reuse** — proven by moving a closed PID's file to `archive/` and showing that (a) `max(NNN)+1` does not walk backwards and (b) re-creating that `NNN` in `pids/` still fires the alarm. Without this case the archive guard is an untested branch, which is the same defect one level up.
- `max(NNN)+1` is emitted from the same scan and is shown to advance when a PID is added.
- A `pids/` file missing a required front-matter key **stops the generator loudly**, proven by removing a key. And a tool that cannot be made to run at all is itself the finding — an unrunnable check must not read as an absent problem.
- `PID-PRINCIPLES.md`, `PID-TEMPLATE.md` and the global rules are present and **byte-identical** to the staged versions.
