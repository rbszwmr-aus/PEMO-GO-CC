# GEN-037 — N1: notices schema and the platform attachment reference (cut A)

**ADR-019 origination only.** The notice becomes a thing PEMO can hold a record of;
composing, approving and publishing one is `N2`, and the acknowledgement surface is
`N3`. **No write surface, no route, and no contract change.**

- **D1/D2** `notices` schema; the notice as an ADR-013 assertion chain, current =
  `MAX(version)`, with lifecycle **computed** by `notices.notice_current` and no
  stored mutable state and no UPDATE path.
- **D3** the targeting rule on the assertion — hierarchy nodes, an ADR-003
  Location for the serving-scope case, and the deliberately empty OQ1 slot.
- **D4** the audience snapshot table, and the resolver — composed from Property
  Core's serving scope and a **new** resident-side occupancy capability.
- **D5** append-only acknowledgement, one effect per key by constraint.
- **D6** the notice-type vocabulary, declared once and projected into module and DDL.
- **D7** `platform.attachment_ref`: no bytes, no object store chosen, opaque
  `storage_ref` by design.
- **D8** a seeded notice targeting the GEN-006 partial-floor lift.
