# GEN-062 — the governance battery must not assume pids/ exists

## The red, and how it was found

Closing GEN-056 emptied `docs/governance/pids/` — the FIRST close to leave no open PID (GEN-061's close
still had GEN-056 in flight). The GEN-056 close-push run on main
([33936770015](https://github.com/rbszwmr-aus/PEMO/actions/runs/33936770015)) reddened the `register`
job: `cp: cannot stat '.../docs/governance/pids/UI-062.md'` and `cp: cannot stat '/tmp/tmp.*/pids'`,
then seven pid-index guard bites reported `expected N, got 0` — "the mutation was NOT caught". The
guards were not weakened; the battery could not run.

**Root cause — `[git-tracking-is-not-existence]`.** git does not track an empty directory. prove.sh
already handles an *empty* `pids/` (GEN-046's synthetic victim), but assumed the directory itself
exists. On a fresh CI checkout of a commit where `pids/` is empty, git materialises no `pids/` at all,
so the snapshot (`cp -a "$GOV/."`), the synthetic victim (`cp "$SYNTH" "$SNAP/pids/"`) and `restore()`
all cp against a directory that is not there. It passed my pre-push hook because my local worktree
still had the empty directory lingering on disk — the classic shape of this principle: the on-disk
remnant hides the absence that a clean checkout exposes.

## The fix (two parts, root + defense)

- **`docs/governance/pids/.gitkeep`** (tracked) — keeps `pids/` present in git even with no open PID.
  It is not a `*.md`, so pid-index (which globs `pids/*.md`) and the synthetic-victim path are
  unaffected. This is the root fix: the directory now survives an empty state.
- **prove.sh `mkdir -p "$GOV/pids" "$GOV/archive" "$GOV/reports"`** before the snapshot — the belt to
  that braces, so the battery never assumes into existence the directory it works in. Verified: with
  `pids/` removed entirely (the CI condition reproduced), prove.sh now runs green.

## The guard and its bite

- **`docs/governance/bin/pids-dir-tracked.mjs`** — reds if git tracks nothing under `pids/`, wired into
  the prove.sh battery so it runs in CI. The keeper cannot be removed silently again.
- **Bite (proven by making it fail):** `git rm --cached docs/governance/pids/.gitkeep` → the guard reds
  naming the cause ("nothing under docs/governance/pids/ is tracked by git"); re-add → green. The
  natural experiment is stronger still: run 33936770015 is the register job reddening for exactly this
  reason, and the fix greens it.

## Principle

Cites the registered `[git-tracking-is-not-existence]` (GEN-001, GEN-011); a worked note for GEN-062 is
added there — the battery layer, one scale up from the migration and PID-file instances.
