# GEN-015 — apply ADR-013 to occupancy

`ADR-013` (the append-only assertion model) is accepted. Occupancy is the **first** state-change table, so this PID both retires `GEN-013`'s deferred end path **and** builds the shared reader-resolver (`D4`) every later state-change table reuses.

## Step 1 — assess, propose, rule-seek. Nothing built.

1. Read `0022` in full: columns, the occupancy **instance identity**, constraints, how `isActiveAt` reads today, the seed rows.
2. Propose the migration — a **new** file: `version`, `recorded_at`, valid-time where absent, `UNIQUE(instance_id, version)`, existing rows reinterpreted as `version = 1`.
3. Propose the shared resolver (`D4`) — *resolve `MAX(version)` per instance as-of the query, then evaluate that assertion* — where it lives, its signature, how `isActiveAt` is rewritten onto it. **Designed to be reused, not occupancy-specific.**
4. Rule-seek on `D5`: does the model require **one active occupancy per unit**? With evidence. If yes, propose the mechanism and its trade-off; if no, `D5` is a no-op here.
5. Build plan and weight estimate, so the Brain can decide whether to **split** the migration + resolver + reader rewrite from the end write.

## Steps & stops

Step 1 → `reports/GEN-015-step1.md`. **HARD STOP** — the Brain rules the migration shape, the resolver design and the `D5` mechanism before any implementation.

## Delivered scope, and the split

**GEN-015 delivered SLICE A only:** the new migration `0117_resident_occupancy_assertions`
(instance identity, `version`, `recorded_at`, `UNIQUE (occupancy_id, version)`, explicit
`version = 1` backfill), the shared reader-resolver `latestAssertionSql` in `modules/platform`,
and the rewrite of occupancy's two readers and `isActiveAt` onto it. Behaviour-preserving:
the 327 pre-existing tests stayed green, and `status` was demoted to data with no liveness role.

**The occupancy END write spun to a NEW PID (Slice B)** — the additive half: the end write
surface, its contract, the one-live-occupancy-per-`(resident, unit)` cardinality mechanism, and
the `auditedWrite`/`ModuleDb` widening that mechanism needs. It was split from A deliberately:
A is a silent read-path rewrite whose whole risk is an invisible resident-authorization
regression, B is additive with novel concurrency machinery, and landing both together would put
those two failure modes in one diff.
