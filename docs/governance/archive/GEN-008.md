# GEN-008 — Battery hardening: four principle carries and three checks

Sequenced ahead of the write skeleton on purpose. Three register-vs-reality truths have no check and each has already cost a defect: the seed partial-world bit `GEN-003`, `GEN-006` and `GEN-007`; the merged-but-draft gap drifted `GEN-006`. Principle 11 is explicit — a class that recurs after being noticed is closed by building the check, not by noticing it a fourth time. This PID builds the floor every later PID stands on, the write skeleton included.

## What to build

**Four principles into `docs/governance/PID-PRINCIPLES.md`**, each earned and each living only in a drive ruling today:

1. A test that asserts a specific expected outcome catches its own decay; one that asserts only "no fault" rots silently. *(`GEN-003` post-close)*
2. A guard's false-positive rate is a safety property: a check that cries wolf gets switched off, and a switched-off check protects nothing. *(`GEN-003` post-close)*
3. A guard that validates, mutates, then hits a second failure mid-mutation is worse than none — it half-applies before anyone knows. All preconditions before any mutation. *(`GEN-006` §A)*
4. Merging a PID and closing it in the register are two acts; releasing the commit orders the merge and nothing else. Every close is its own instruction. *(`GEN-006` close)*

**Check A — `BOUNDARY_TARGETS` derived, not hard-coded.** The battery's injection targets are still two literal source paths — the frozen-axis class the `GEN-003` close named and the `GEN-006` close was bitten by. Derive them at runtime so no injection target is a hard-coded committed-source path.

**Check B — seed reproduces from nothing.** No test asserts `migrate; seed` completes and yields a complete world; that absence bit three PIDs. Build the assertion, and because it needs a database and toolchain it must **fail loudly where the toolchain is absent, never skip green** — the `REQUIRE_DEPCRUISE` lesson. Assess at Step 1 whether it lives as a CI job step or a battery case, and propose; if it is better as its own PID, say so rather than forcing it here.

**Check C — merged-but-draft.** The register-status-against-shipped-reality direction has no check. A `draft|running` PID whose work is already on `main` should **warn** that it is a candidate merged-but-undrafted — and must state plainly what it cannot distinguish. It warns, names its blind spot, and does not fail the build, the same honesty the orphan guard carries.

## Done when

Each proven by making its red fire — the caught-edge standard.

1. The four principles are present in `PID-PRINCIPLES.md`, each exactly once, counted and grepped.
2. **Check A:** rename an injection target; the battery still finds its victim.
3. **Check B:** inject an F1-shaped omission into a scenario seed; the check fails loudly. Remove it; it passes. And it **fails, not skips green**, when the toolchain is absent.
4. **Check C:** a `draft` PID whose work is on `main` warns; a partially-landed one either does not falsely warn, or warns while naming that it cannot distinguish — show which. The warning fires on the real condition, not a proxy.
