# GEN-011 — The platform audited-write primitive

`GEN-009` proved that the act and its audit land in **different transactions**: each `createModuleDb` owns a pool with its own `search_path`, so the act (a module schema) and the audit (`access`) cannot be atomic. Injecting a failure after both writes left **0 act rows and 1 audit row** — an audit asserting an authorised act that never happened.

That is worse than `ADR-010` D1's stated hazard. D1 warns that an audit written afterwards *can fail separately* — a **missing** record. This produces a **false** one, and for a record whose only purpose is reconstructing authority after an incident, confident wrongness beats silence.

## What to build

**The audited write is a platform primitive, because the audit is cross-cutting.** Fragmenting it into each module's schema is rejected — it destroys the audit's purpose, turning one coherent record into seven. A module reaching into `access` is rejected — it is the boundary violation module isolation exists to forbid. What remains: the audit belongs to the shared layer every module already depends on.

- **The primitive.** One transaction spanning the calling module's schema **and** `access.audit_event`, atomically. The module hands platform the act and the audit fields; platform runs the single cross-schema transaction. Modules never cross; platform, the sanctioned owner, does — once. Its exact shape is proposed at Step 1.
- **The enforcement that it is the *only* cross-schema write path.** `verify-boundaries` scans `modules/` only, so `apps/api` **may** already cross — and *may is not should*. A sanctioned crossing without a check that it is the only one erodes the boundary exactly as an obligation without its guard does (`GEN-010`).

## Done when

Each proven by making it fail.

1. **Atomicity — the false audit is unreachable.** Reproduce `GEN-009`'s test: inject a failure after both writes; **both** roll back. The 0-act/1-audit state must not be reachable.
2. **Commit-both-or-neither, shown both directions.**
3. **The boundary holds** — a cross-schema write attempted outside the primitive is caught by the enforcement, and the primitive itself is recognised as sanctioned.

## Steps & stops

Step 1 → pin; propose the primitive's shape and the enforcement's design → `reports/GEN-011-step1.md`. **HARD STOP.**
Step 2 → build; prove the three reds → `reports/GEN-011-step2.md`. **HARD STOP before commit.**

## Note

A precursor like `GEN-010`, and for the same reason: a change to the shared platform boundary, the first cross-schema write path in the codebase, and all 27 scope-only writes depend on it. `GEN-009` holds and resumes on it.
