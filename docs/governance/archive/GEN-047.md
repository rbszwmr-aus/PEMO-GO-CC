# GEN-047 — notices 2.1.0: permitted actions, state-entered, fixture parity, UI-045 findings

## What to build

management-web `2.0.0` → **`2.1.0`, MINOR, ADDITIVE ONLY**. This is what UI part 2
binds to. Cites `ADR-019`, `ADR-017`, `ADR-018`, `ADR-008`, `ADR-007`, `GEN-040`,
`GEN-042`, `GEN-043`, `GEN-006-ST`, and `UI-045-step1` sections G1–G7 on `main`.

- **D1 — permitted actions, derived from the act floors** (`UI-045` F6). On
  `listNotices` items and `getNotice`: `permitted_actions: string[]`, a subset of
  revise / submit / approve / decline / publish / correct / withdraw — the ones
  **this caller** may perform on **this notice now**, by dry-running each act's own
  floor and state precondition. **ONE SOURCE:** a shared `canPerform(act, notice,
  caller)` that the acts themselves call before executing, never a parallel hand
  list. The client renders a control iff its act is listed, and reasons about no
  role. Content refusals (bilingual, empty audience) are shown, not predicted.
- **D2 — state-entered** (`UI-045` G5). `state_entered_at` on list and detail: the
  timestamp of the assertion that put the notice in its current **computed** state.
  A-05's oldest-first approval queue is not implementable without it.
- **D3 — fixture parity** for every `GEN-042` operation (`GEN-006`; a breach the
  PO's close ruling missed): 8 staff writes (request + response + one refusal
  problem), 3 resident acts, R1 `getMyNotices`, R3 `getNoticeOutstanding`. Bound to
  the seeded world. If no parity CHECK exists, build one — **an operation without a
  fixture must be a RED, not a report line.**
- **D4 — `UI-045` findings G2–G7:** each becomes a MINOR change here or a NAMED
  deferral with its reason. None dropped silently. (G5 is D2.)
- **D5 — S2 overview `NoticeRow`:** touch ONLY if a G-finding requires it — that is
  a MAJOR, so say so and HARD STOP for a ruling. Otherwise leave it, named.
- **D6 — disjoint vocabularies:** `state_entered_at` and `permitted_actions` key on
  the LIFECYCLE vocabulary, with a type-level test that a disposition literal
  cannot be passed where a lifecycle state is expected.

**Out of scope:** resident-mobile beyond fixtures (unless a G-finding requires it —
then MINOR, stated); templates; Notification; cases; the ~36 prose bites (the next
governance PID); **all CI changes**.
