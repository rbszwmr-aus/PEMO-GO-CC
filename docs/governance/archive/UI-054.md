# UI-054 — Notices part 2b: property-tree compose entry, 2.2.0 bindings, live act exercise

## What to build

The follow-ups the `UI-051` step and close rulings named, against contract `2.2.0`
(`GEN-052`: the wrong-state and stale-version refusal fixtures, the `reasonCode`
enum, `submitNotice` removed from ungated drafts) and with `GEN-050`'s dev-token
command available for a live exercise. Same discipline as `UI-051` throughout:
URL = state, no client identity or role concept, affordances read never reasoned,
four states × two locales each failing for its own reason, the `UI-045` R1
mutation criterion, the data-claim register complete.

- **D1 Compose entry on property-tree nodes** (`UI-051` G6, ruled). Every node of
  `getPropertyTree` that lists `composeNotice` offers the entry; `getScope` keeps
  only the shell. Bite: entry drawn from node kind or depth instead of the list →
  reds on the fixture where a floor lists it and a sibling does not.
- **D2 2.2.0 bindings.** Wrong-state and stale-version bound as distinct states,
  distinguished by TYPE. `reasonCode` as a select from the generated enum with
  per-act subsets derived from the contract, free text gone; bites: a non-enum
  code offered → type error; a hard-coded subset → reds. Every `UI-051` assertion
  moved by `GEN-052`'s fixture corrections re-bound and named.
- **D3 Guide.** The dev-token usage line in the local try-out guide's live-mode
  section; caller selection becomes "what you can do".
- **D4 Live act exercise — report, not gate.** Dev-token against the local API and
  seeded world, covering / non-covering / dual-role: compose→submit→approve→publish
  on a gated type; compose→publish on an ungated type; one refusal of each fixtured
  kind. Matches and mismatches verbatim; mismatches are G-findings. No test depends
  on the live server.
- **D5** `inventory-complete` compares against what the runner collects, not typed
  totals. Bite: a test added without an inventory entry → reds.
- **D6** G7 column iff ruled by then; else the named deferral stands.

**Out of scope:** grant admin; cases; resident app; attachment upload; any change to
contracts, fixtures or generated files. A missing or wrong fixture is a G-finding and
a HARD STOP on that item. A corpus change landing mid-flight is re-bound on this
