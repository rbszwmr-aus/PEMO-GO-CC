# GEN-005 — Close GEN-001's three carried items

## What to build

Three corrections GEN-001 proved necessary but did not apply, because a build
proven through twelve firings does not take unproven last-minute edits.

1. **Remove `reports:` from the front-matter schema; derive a PID's report list
   from the directory by `<ID>-` prefix.** The glob disagreed with the directory
   UNIFORMLY across all three PIDs that have reports, because
   `reports/<ID>-step*.md` cannot match a ruling file and rulings are now
   first-class evidence — GEN-001 itself was released by one. Uniform
   disagreement means the declaration is stale, not the directory. This is
   frozen-axis in its exact shape: the world grew, the hand-written list did not.
   Update PID-TEMPLATE.md, the generator, and every existing pids/ and archive/
   file.

   **After the key is removed, `reports:` becomes an UNKNOWN KEY and the
   generator REJECTS it — it is not silently ignored.** Two reasons: a tolerated
   leftover would linger as a human-misleading declaration of exactly the kind
   that just drifted uniformly across three PIDs, and "unknown key is an error"
   is the same no-safe-default discipline the classifier already uses.

   This file carries `reports:` itself, added deliberately so that GEN-001's
   schema would accept it — the alternative was landing an unproven schema change
   ahead of the PID that authorises it. Deleting that line is item 1's own live
   test, not a chore.

2. **Add to PID-PRINCIPLES.md**, two principles.

   "A fix can open a new failure mode, and the check written for the old world
   cannot see it. Strengthening a rule changes the space of reachable
   corruptions. When you amend a rule, re-ask what the EXISTING guard can no
   longer see — the new hazard is usually adjacent to the thing you just made
   load-bearing, and the guard will keep passing while blind to it." Incident:
   rule 7's file-moves amendment made the archive leg load-bearing and
   simultaneously made shape (b) reachable, and the reference one-liner could not
   see it because sort -u collapses the pair before the number is extracted.
   The principle's first confirmation was the PID that files the principle:
   removing `reports:` made the very next file the existing guard saw — this one
   — break against it, the hazard sitting immediately adjacent to the field being
   made obsolete.

   "A check that is expected to be red is a check that stops being read. A guard
   may be red only while someone is actively fixing it; a knowingly-red guard
   left standing teaches people to skip the output, and it takes the guards
   beside it down with it."

3. **CI runs the generator's `--check`.** It must run from a clean checkout and
   fail the build on any non-zero exit, with the exit code surfaced so the fault
   is named rather than "it failed". The tracked-file check announcing its skip
   out loud (rather than skipping silently) must survive into CI — a check that
   goes quiet in the environment that matters is worse than one that is absent.

## Done when

  in the generator; the report list is derived, and a PID whose reports include a
  ruling now lists it — proven on GEN-001, which has one.
- A file carrying `reports:` after the change **exits non-zero and names it** —
  proven by leaving one in, not by reading the code.
- The generator still reproduces PID-INDEX.md byte-for-byte after the schema
  change, and every GEN-001 acceptance still fires for its own exit code

  failure this PID is most exposed to).
- CI fails on an injected fault and NAMES it — proven by injecting one, not by
  configuring one.
- Both principles are present in PID-PRINCIPLES.md with their incidents attached.
