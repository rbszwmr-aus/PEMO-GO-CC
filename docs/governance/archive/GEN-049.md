# GEN-049 — notices: a deterministic publish bite, and a race is not a bite

Owed by the GEN-047 step-1 ruling (a). `docs/governance/mutations/manifest.json` carries
`publish-advisory-lock` as `status: unreliable`: the lock is load-bearing (the mutation reds
6/6 when case 12 runs alone) but the bite cannot force the interleaving (one run in three as
the whole file). A timing-dependent red is a claim. This PID makes it a proof.

## What to build

Decide by what the advisory lock ACTUALLY guards, and say which:

- **(i)** If `ADR-019`'s lifecycle makes "at most one publish assertion per notice" an
  invariant (withdrawn is terminal; correct cannot re-publish), replace the advisory lock
  with a **partial unique index** — the N3 pattern already ruled for acknowledgement — in a
  NEW migration, and map the violation to the existing state-conflict Problem. The bite is
  then deterministic: two connections, an open transaction on A holding the first publish,
  the second publish on B — refused with the index, succeeds without it.
- **(ii)** If the lock guards MORE than uniqueness (name the specific thing — e.g. the
  approval read + audience snapshot as one critical section), keep the lock and make the
  test deterministic the same way: A holds the lock key inside an open transaction; B's
  publish is asserted to block and time out under `lock_timeout`; under the mutation B
  completes.

Either way the test forces the interleaving with two connections and an open transaction.
**It never waits for a race to happen.**

Add the principle `a-race-is-not-a-bite` to `PID-PRINCIPLES.md` — backticks here; a
bracketed citation only in the commit that defines it. Flip the manifest entry from
`unreliable` to a proven red under the four-condition runner.
