# GEN-030 — W3 batch 3: the bootstrap, membership, and the unified guard

The authority-creating surface, and the guard that keeps an organization administrable.

Step 1 proposes six things and builds nothing. One of them does not survive contact: **the bootstrap
is still not self-contained**, one level below the gap `GEN-027` found.

## Steps & stops

Step 1: proposal → `reports/GEN-030-step1.md`. **No build. HARD STOP.**

## Archive note — 3a delivers the GUARD and the COMMANDS. The DBA is NOT gone.

**What landed:** the unified guard over EFFECTIVE administrators (grant AND membership, one witness
query, both routes, plus a shared organization lock that makes "no live effective administrator" an
invariant rather than a per-request opinion), and the `addMembership` / `removeMembership`
**commands** with G-2-per-live-grant and the administrator floor.

**What did NOT land, and what each still blocks:**

- **Routes.** These are module-level commands with no write surface — no route, no contract, no
  problem types. They ride `3b`/`3c`. **Nothing outside the codebase can call them.**
- **The bootstrap** (`3b`) is blocked on an identity decision: `group_membership.principal_id`
  foreign-keys `access.staff_principal`, and **nothing in the system creates one** — only the seed.
  So a genuinely empty organization still has no person to seat.

**The DBA is gone only once ROUTES and BOOTSTRAP both land.** `W3` is not finished.
