# GEN-064 — Overview has one source per counter (the contract/API half)

Binding order: **GEN-064 merges and closes BEFORE UI-065 (UI CC) is dispatched.** UI CC does not build
actionable affordances over numbers and a picker that have no trustworthy source. Rulings:
`reports/GEN-064-RULINGS-overview-shape-and-split.md`, `…-amendment-1-the-mockup-is-the-target.md`,
`RULING-design-authority-and-the-stale-mockup-2026-09-05.md`.

Registered principles this PID serves: `[a-surface-that-displays-without-a-source-is-a-drawing]`,
`[a-screen-that-renders-the-same-with-and-without-its-read-has-no-read]`.

## D1 — one source per counter (G7 in a second setting: the server counts, the client never counts)

**Narrowed by Amendment 2 to THREE counters** — `open-cases` leaves this PID (see below). For each of
`notices-active`, `safety-events-window` (24h), `units-unknown-state` deliver:
1. a **stated definition** in the contract operation's description: the predicate AND the deduplication, in prose;
2. a **scope-parameterised list operation** returning exactly the rows that satisfy that definition;
3. the counter on `getOverview` computed from that SAME definition — never a second query that agrees.

Per-counter definitions, ruled (Amendment 2):
- **notices-active** = `lifecycleState:['live']`. Do not restate the predicate — CALL `notices.notice_current`
  via the existing `staff-notices.list(org, scopeNodeKeys, {lifecycleState:['live']})` (already wired,
  `server.ts:2311`); the count is a sibling from the IDENTICAL `INTERSECTS` + state predicate. Label and
  stated definition say **"live now"**, not "active".
- **safety-events-window** = DISTINCT `event_id` over `safety_event_audience` (unit ∈ expanded scope),
  `occurred_at ≥ now()−24h`, `retracted = false` — on BOTH count and list. Count DISTINCT events, never
  audience join rows (`[count-the-thing-not-the-rows-that-mention-it]`). `windowHours` carried in the
  response, the value the definition used; never a client constant. Late arrivals (occurred>24h ago, just
  received) are NOT counted — recorded debt against `attention[]`, not solved by moving the window.
- **units-unknown-state** = `severity ∈ {unknown, offline}` over **residential** units in scope
  (`unit_class='residential'`, matching `tree-queries.ts:70`); `basis.includesSeverities` reports exactly
  that; dedup is STRUCTURAL (`unit_safety_state` PK is `unit_id`), so `deduplicatedByUnit:true` is true
  because of where we counted — say so. Never count via `installed_service`. `monitoring_coverage` is NOT in
  the definition (a contract change if it belongs — report first).

`basis` is derived from the applied definition, not typed beside it. The trap forbidden is click-31-see-28.

## open-cases — OUT of GEN-064, and ABSENT (not zero) from the response

Amendment 2 (D2/D3): `service_case` carries no scope, and resolving one through `originating_ticket_ref`
reads provenance as a join (`[provenance-is-not-a-join]`), re-creates the coupling ADR-020 removed, and is
wrong at the edges (a case with no ticket vanishes; a two-ticket case has no single scope). `open-cases`,
`listCases` and the Cases screen leave this PID, awaiting the Brain's ADR-020 amendment (a case carries its
own scope). GEN-064 **omits** `open-cases` from `OverviewResponse.counters` — omitted, not `0`, not null
(`[absence-is-not-zero]`); UI-065 draws nothing where a key is absent.

## D2 — getOverview(scope) is a projection

Scope argument follows the existing `parseScopeParam` convention (`server.ts:1343-1357`); a node outside
the caller's grant union throws `scopeNotFound` exactly as `composePropertyTree` does
(`compose-trees.ts:208-215`). **No new refusal vocabulary** — if `getOverview` needs a Problem shape 2.2.0
lacks, REPORT it, do not invent it. **No `permittedActions` on counters** (Overview is a read surface); if a
tile is found to offer an act, report before adding.

## D3 — no search endpoint

`composeScopeTree` is already grant-limited and server-filtered, so client-side search over the returned
nodes discloses nothing and needs no contract change (that is UI-065's, client-side). A server-side search
is authorised only on a returned finding naming which it hit: measured node count too large to
hold/filter responsively (with the number), matching over fields the tree does not carry, or ranking/paging
the client cannot do. Absent such a finding, none is built here.

## D5 — the scope-summary counts and the tree row counts are server-owned, and obey D1

The shell scope summary (`Wing Fu Garden 榮富花園 / 3 blocks · 812 units`) and the tree's own row counts
(`812 units` / `268 units` / `8 flats`) are counters: server-produced under one stated definition, never
assembled client-side by walking the returned tree. A row that says `268 units` and expands to `265` is the
same trap in a second costume. `occupied` / `vacant` on a leaf is a **server-owned state**, not a client
inference from an empty household array. GEN-064 carries these counts.

## The bites are proven by test-constructed props (Amendment 3)

The seed is too quiet — `0 == []` proves nothing — so each teeth-bearing predicate is proven by data the
suite constructs and tears down (`[the-seed-is-the-world-the-fixture-is-a-photograph-the-test-builds-its-own-props]`).
Four required constructions, each with its instrument control (remove the condition → the named assertion
reds → restore), reported at close:
1. a safety event whose audience spans several units → DISTINCT `event_id` (join-row count differs from event count);
2. a retracted event inside the 24h window → `retracted = false` has teeth;
3. a non-residential unit carrying an `unknown` severity → residential-only has teeth;
4. occupancies under ≥2 buildings → the tree count is proven PER NODE, not per estate.
