# GEN-048 — CI hardening: the Flutter toolchain, and verifying the browser job

Parallel to `GEN-047`, and deliberately NOT folded into it: `GEN-047` is a contract
PID and must not carry CI changes. Decided by the PO on 2026-09-02 in
`docs/governance/decisions/DECISION-flutter-ci-and-browser-job-verification-2026-09-02.md`.

## What to build

- **D1 — the Flutter toolchain into CI; gate `apps/resident-mobile`.** The workflow
  installs a **PINNED** Flutter SDK — an explicit version, no `latest`, no `stable`
  channel float — and a job runs `flutter test` over `apps/resident-mobile`. Its **8
  existing `*_test.dart` files are gated as they stand; this PID adds no new Dart
  tests.** A red there blocks merge exactly as a management-web red does. Cache the
  SDK if the runner supports it: **caching is optional, the pin is not.** State the
  pin in the workflow and in the close report. Do not touch
  `apps/resident-mobile/**.g.dart` or any generated file — `GEN-047` may regenerate
  those; this PID may not.
- **D2 — verify the CI browser job.** Read the GitHub Actions run for `75d92fe` AND
  the run for this PID's own merge. Report **verbatim per run**: workflow name, job
  name, conclusion, duration. For the browser job, **quote the runner log line that
  names the browser and version** the suite ran under. **A green with no browser
  line is NOT verified** — report it as "green, browser unproven" and diagnose why
  the line is absent. If the `75d92fe` run did not execute the browser job at all
  (path filter, skipped, cancelled), say so and **name the diagnosed cause, not the
  symptom.**

## Proof — the corpus standard

- **Flutter job:** one instrument check. Break one resident-mobile test on a
  throwaway branch (or via a `with-mutation.sh` equivalent) and show the CI job goes
  red with a **named assertion failure**, not a build or toolchain error; then
  restore. **If the harness cannot re-run it, record it in
  `mutations/manifest.json` as a CLAIM, not as proven.**
- **Browser job:** the browser/version log line from D2 is the proof.

## Stop conditions — name the diagnosed cause

- The Flutter SDK pin cannot be resolved on the runner image.
- **Any of the 8 resident-mobile tests is red on `main` before this change** —
  report which and why; do NOT fix them in this PID.
- The browser job on `75d92fe` ran under a node fallback rather than a browser.

## Close report

Flutter version pinned; job name; run URL; the 8 test names and their results. The
D2 table: run × job × conclusion × duration × browser line. The
`mutations/manifest.json` diff, proven versus CLAIM. And the owed items this PID
does not touch: harness classes for the ~36 prose bites; the exact projection type;
the multi-node ticket case; context-scoped citation recognition.
