# GEN-033 — W3 batch iii: the three write-surface routes

**The last piece of W3.** `registerPrincipal`, `addMembership` and `removeMembership` are built,
guarded and **unreachable**. This wires them behind `ADR-017`'s delegation floors, so an organization
can be given a second person and administered end to end.

**The DBA is gone only once this lands.**

`W3 batch iii` is a label; the id is the register's allocation.

## Archive note — W3 IS COMPLETE. The DBA is gone.

An organization can now be brought into existence, given a second person, and administered end to
end, without anyone touching the database:

| act | route | floor |
|---|---|---|
| genesis | `POST /organizations/{id}/provision` | zero grants **EVER**, once-only |
| record an identity | `POST /principals` | effective `grant_administrator` @ the **organization** node |
| confer / revoke a grant | `POST /grants`, `.../revoke` | `G-2` at the grant's node |
| seat / remove a member | `POST /groups/{id}/members`, `POST /memberships/{id}/remove` | `G-2` **lifted to the set** the group confers at; removal also passes the no-last-effective-administrator guard |

**The one thing to carry forward** (`GEN-033` gap 2, held out at close): **the floor trusts the
caller's node set.** Every `G-2` site takes an expanded node set from the composition layer and
cannot verify it was filtered to `grant_administrator` grants. The three routes here filter
correctly, and a future route that passed the expansion of *all* the caller's grants would silently
widen every floor to *any grant anywhere* — with nothing to catch it. Not a defect today; a shape
that only holds while every caller is careful.
